## Required behavior

Close specs/system/activity-dashboard.md (single section, audit gap dba01522c9fb7fb9aa3be898, failure modes (a)-(f)). All five bullets must hold in production code. (1) Real-time feed over ANY time period: (a) time period — the unified GET /api/v1/activity handler (crates/gyre-server/src/api/activity.rs) must honor its declared-but-ignored `since` query parameter (epoch seconds) against DURABLE storage: extend NotificationRepository (crates/gyre-ports/src/notification.rs) with a general time-filtered feed query (e.g. list_since(since, limit): created_at >= since, ordered created_at DESC — distinct from the existing type-specific list_by_workspace_type_since) implemented by EVERY adapter implementing the port (mem in crates/gyre-server/src/mem.rs, SQLite in crates/gyre-adapters/src/sqlite/notification.rs, PostgreSQL in crates/gyre-adapters/src/postgres/notification.rs — port-contract invariant), and make the handler execute the filter in the repository, not by post-fetch truncation; web/src/lib/api.js activity() forwards the since parameter. (b) real-time — the SPA activity sidebars (web/src/components/WorkspaceHome.svelte and CrossWorkspaceHome.svelte) must stop being one-shot snapshots per workspace-scope change: subscribe through the app's single shared /ws connection (web/src/lib/ws.js onMessage, the channel notifications.svelte.js already rides) and live-prepend bus Messages delivered for the subscribed workspace (the server already broadcasts telemetry/event-tier Messages via message_broadcast_tx, and ws.rs delivers them only to subscribed same-tenant members with per-workspace membership enforcement — that server-side isolation is existing behavior and must be preserved); map incoming messages to the same entry shape the /activity handler returns, dedupe by id, and on reconnect re-sync via GET /api/v1/activity?since=<newest entry timestamp>. (2) Artifact links: every activity entry referencing an artifact navigates to it — MR/agent/task/spec entries (existing nav()) plus gate-failure/test-result entries landing on the MR's gate output, with entries surfacing the artifact refs they carry (mr_id, repo_id, agent_id, task_id, spec_path, and any commit/branch/gate refs present in the notification body) as deep links; no feed entry with a resolvable artifact may be a dead end. (3) 'Try it' links — ephemeral preview environments for completed work: a durable PreviewEnvironment entity through gyre-ports (new port trait) + SQLite migration (next unused 6-digit sequence number; latest committed is 2026-11-20-000069_scim_group_member_display, so the next is 000070) + mem adapter, wired with the store! pattern — NEVER an in-memory Arc<Mutex<HashMap>> AppState field (durable-state invariant). REST surface: POST provisioning (MR-scoped, e.g. /api/v1/mrs/:id/try-it, for the MR's merged commit; a repo+ref form is acceptable) plus GET (list/status) and DELETE (teardown). Provisioning is real: dispatch through the existing compute-target machinery (spawn.rs dispatch_agent_launch / crates/gyre-ports/src/compute.rs ComputeTarget) to run a container built from the NixOS flake-based image path with a checkout of the artifact's commit, using isolated scratch state (its own temp data dir — it must NOT touch the production database/storage), and register the environment as a WireGuard mesh peer (network.rs register_peer, mesh IP allocation) so the requesting user can reach it over the platform's encrypted overlay network — the platform's realization of the specced 'NixOS + Tailscale' ephemeral environment; the behavioral contract is: ephemeral, isolated from production, running that exact version of the code, reachable by the user over the mesh. Lifecycle: status provisioning -> active -> expired/failed with a TTL expiry/teardown job on the existing jobs.rs scheduler that terminates the environment and removes its mesh peer. Every new route gets an ABAC RouteResourceMapping entry in abac_middleware.rs (registry invariant — no exemption-file entries) and per-handler workspace-membership/tenant scoping. UI: merged-MR activity entries and the MR detail surface render a 'Try it' action that provisions, shows live status, and tears down. (4) Human window into the Ralph loop — TTY attach must be reachable from the product UI: a TTY viewer component that opens the existing authenticated /ws/agents/:id/tty WebSocket (crates/gyre-server/src/tty.rs already replays buffered agent log lines then streams live output), mounted from agent surfaces (agent detail panel and/or activity entries referencing a running agent) via the currently-dead web/src/lib/api.js agentTtyUrl helper; 'see what's happening' = (1), 'spin up a preview' = (3), 'give feedback' already exists (notification inbox + approve/reject decisions) and must be preserved unchanged. (5) Feeds analytics — what users actually TRIED: provisioning records a real AnalyticsEvent via state.analytics.record (e.g. 'preview.started' carrying user_id, workspace_id, repo_id, mr_id/ref in properties) and teardown/expiry records 'preview.ended'/'preview.expired', making the trial half of the analytics feed real; the approve/reject half (spec.approved, mr.merged, mr.closed, agent.completed/failed, task.status_changed) already exists and must be preserved. Note on concurrent work: the assigned ui-layout plan (spec-72f70a7108d07f5ab2fb9e3e) also touches WorkspaceHome.svelte for the specs table/explorer surfaces — scope frontend edits in this task to the activity sidebar, TTY viewer, and try-it affordances to avoid collision; this is file-hygiene, not a behavioral dependency.

## Acceptance Criteria

- [ ] GET /api/v1/activity?since=T excludes durable notifications with created_at < T and includes newer ones, newest-first; the filter runs in the repository layer of every adapter implementing NotificationRepository (mem + SQLite + PostgreSQL), and web/src/lib/api.js activity() forwards since.
- [ ] With the dashboard open on workspace W, a bus message emitted for W (emit_telemetry / event emit) appears in the activity sidebar without reload or scope change, while a message for a different workspace does not (vitest feeding the shared ws store).
- [ ] POST try-it for a merged MR creates a durable PreviewEnvironment row (queryable after a server restart against SQLite) carrying the resolved commit SHA, drives provisioning through the compute-target machinery, registers a WireGuard mesh peer for the environment, and exposes status; DELETE and TTL expiry terminate it and remove the peer.
- [ ] A same-tenant non-member caller receives 403 on the try-it routes with no preview row and no mesh peer created; a request naming an unresolvable MR/ref receives 4xx with no side effects.
- [ ] A 'preview.started' AnalyticsEvent with user/workspace/repo/mr properties is recorded on provisioning and queryable through the analytics query API; teardown records the corresponding end event.
- [ ] An agent surface renders an Attach-TTY control that opens the /ws/agents/:id/tty socket and displays replayed then live lines (vitest asserts the socket URL from agentTtyUrl is actually consumed); agentTtyUrl is no longer dead code.
- [ ] Every activity entry with a resolvable artifact deep-links to that artifact's detail, including gate-failure/test-result entries landing on the MR's gate output.
