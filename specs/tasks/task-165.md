## Spec Excerpt

### §gyre-stack.lock (supply-chain.md)

A lockfile (`gyre-stack.lock`) captures the full reproducible state of the agent stack. It is generated by the CLI and committed to the repo, allowing verification that the stack hasn't drifted between commits.

### §Attestation Levels (supply-chain.md)

| Level | Name | Meaning |
|---|---|---|
| 3 | Gyre-Managed Runtime | Server-verified container with workload attestation |
| 2 | Gyre CLI on Developer Machine | Self-reported stack fingerprint |
| 1 | Raw Git Push | No attestation — lowest trust |

### §Policy per Level (supply-chain.md)

Repos can set minimum attestation level requirements. Pushes from agents below the minimum level are rejected or flagged based on policy.

## Implementation Plan

1. **gyre-stack.lock format**: Define the lockfile schema (TOML or YAML) capturing: agents_md_hash, hooks, mcp_servers, model, cli_version, settings_hash, persona_hash, lock_timestamp. Parse this file from the repo's git tree during push processing.

2. **Lockfile generation**: Add `gyre stack lock` CLI command that generates `gyre-stack.lock` from the current agent configuration.

3. **Attestation level enforcement**: Currently the system defaults to Level 2 for all agents. Implement:
   - Level 3 detection: if the agent is running in a Gyre-managed container (check `wl_compute_target` JWT claim), attestation is Level 3
   - Level 1 detection: if no stack attestation was submitted, attestation is Level 1
   - Store the resolved attestation level on the agent record

4. **Stack policy per-level**: Extend the repo stack policy to include `min_attestation_level: u8`. On push, compare the agent's attestation level against the policy minimum. Below-minimum pushes are rejected (Block mode) or flagged (Warn mode).

5. **Drift detection**: Compare `gyre-stack.lock` in the repo with the submitted stack attestation. If they differ, flag as stack drift.

**Actual behavior (from the two checkpoints, re-verified at this HEAD):**

1. **Lockfile schema** — `StackLockfile` (`crates/gyre-domain/src/stack.rs`):
   TOML schema with fingerprint + agents_md_hash, hooks, mcp_servers, model,
   cli_version, settings_hash, persona_hash, lock_timestamp.
   `parse()`/`to_toml()` round-trip, `verify_integrity()` recomputes the
   composite fingerprint from components, `check_drift()` names differing
   components. Lives in gyre-domain so CLI and server compute the same
   fingerprint over the same schema.
2. **Lockfile generation** — `gyre stack lock [--output PATH]`
   (`crates/gyre-cli/src/main.rs:1631-1655`): fetches the agent's registered
   stack via `GET /api/v1/agents/:id/stack` and writes the TOML lockfile.
3. **Attestation level resolution** — `resolve_push_attestation_level`
   (`git_http.rs:1265-1307`): L3 = server-recorded workload attestation with
   container identity (written by spawn.rs for M19.4 container targets) or
   verified agent JWT carrying `wl_container_id`+`wl_image_hash`; L2 =
   registered stack in KV `agent_stacks`; L1 = no attestation. Stored on the
   agent record (migration `2026-10-10-000056_agent_attestation_level`,
   sqlite/postgres round-trip, mem via whole-struct clone), exposed on
   `GET /api/v1/agents/:id` as `attestation_level`, and mapped to commit
   provenance labels (server-verified / self-reported / unattested,
   git_http.rs:516-525).
4. **Per-level policy** — `RepoStackPolicy` (`api/stack_attest.rs:47-61`)
   with `min_attestation_level: u8` (1..=3, validated) and `enforcement:
   block|warn`; Admin-only PUT/GET `/repos/:id/stack-policy`; legacy KV
   entries derive `min_attestation_level` from `required_level`.
5. **Push enforcement** — `enforce_stack_policy` (git_http.rs:1337-1449)
   runs synchronously on every push to a policy-bearing repo: below-minimum
   level → Block: 403 + `undo_ref_updates` + PushRejected event; Warn:
   accept + ConstraintViolation event. `gyre-stack.lock` in the pushed tree
   is read via `read_git_file` at the new SHA, integrity-checked, and
   drift-checked against the pushing agent's attested stack under the same
   enforcement modes.
