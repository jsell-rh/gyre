## Findings

- **F1 (major, code)**: `merge_queue.processed` is not recorded on two production paths that transition a queue entry to terminal `Failed`, contradicting the shipped claim ("every terminal outcome", "every terminal Failed path") and `fail_queue_entry`'s own stated invariant ("Every production path that fails a queue entry must go through here"). Sites: (a) candidate-selection 4b'' non-mergeable-MR check (`merge_processor.rs` ~1210-1231) — `update_status(Failed)` then `continue`, no emission, directly adjacent to the MR-not-found site that WAS wired; (b) atomic-group R4 member non-mergeable check (~731-748) — `rollback_atomic_group` then `update_status(Failed)`, no emission. **Empirically proven**: a temporary probe test (mirroring the existing `process_next_fails_entry_for_reverted_mr` plus the analytics assertion from the shipped `mr_not_found_during_selection_records_queue_processed_failed`) fails with `events.len()` 0 != 1 — the entry reaches Failed with zero `merge_queue.processed` events. Probe source, command, exit code, and output retained in `/tmp/stage/review-evidence/probe-nonmergeable-queue-processed.txt`; the working tree was restored byte-identical after the run. The coverage-matrix row for §Auto-Emitted Events is marked `implemented` with the "every terminal Failed path" claim, which is false (goal rule 3: no fake completion). Fix: route both sites through `fail_queue_entry(state, entry, Some(&mr), "mr_not_mergeable", ...)`.
- **F2 (moderate, code)**: `cancel_entry` (`api/merge_queue.rs` ~103-122, `DELETE /api/v1/merge-queue/:id`) cancels a queue entry to terminal `Cancelled` with no `merge_queue.processed` event, while the circuit-breaker `Cancelled` path emits outcome `"skipped"` for the same terminal state — the branch wired one Cancelled path and not the other. Pre-existing in base; in-scope because the coverage claim asserts complete trigger coverage. Fix: emit with outcome `"skipped"` after a successful cancel.
- **F3 (minor, code)**: `agent.failed` is not recorded on the compose teardown kill path (`api/compose.rs` ~208-218): `teardown_handler` transitions every session agent to `Dead` with no event. Spec trigger is "Agent fails or is killed"; every other kill path emits. Pre-existing in base and not claimed in the shipped enumeration, hence minor. (The stale-agent `Pause` stop in `stale_agents.rs` ~146-158 is defensibly unemitted — a configured graceful stop, not a failure or kill.)
