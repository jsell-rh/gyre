## Findings

- [ ] **F1 (major, missing emission): the ralph-loop gate-failure path persists MR close, agent Failed, and task Blocked transitions with no analytics events.** `crates/gyre-server/src/ralph_loop.rs` (production code, before `mod tests`): `handle_gate_failure` closes the failed MR (`transition_status(MrStatus::Closed)`, ~line 328) — a spec trigger "MR closed without merge" with no `mr.closed` event; at the iteration ceiling it transitions the agent to `Failed` (~line 343) — the canonical "Agent fails" terminal of the core autonomous loop — and the task to `Blocked` (~line 346), with no `agent.failed` / `task.status_changed` events; `respawn_with_retry`'s terminal state (retries exhausted → agent `Failed`, task `Blocked`, ~lines 440+) likewise records nothing. Repro: drive the existing ralph-loop gate-failure tests (e.g. the iteration-ceiling and respawn-retry tests in `ralph_loop.rs` mod tests) and `state.analytics.query(Some("mr.closed"|"agent.failed"|"task.status_changed"), ...)` returns zero events for these transitions. The coverage matrix note "All 12 events emit at real trigger points" is inaccurate for these paths. Repair: emit the three events on these paths (same shapes as the sibling paths) and pin with per-path tests.
- [ ] **F2 (major, unsafe scope handling): `search.query` persists a caller-supplied, unvalidated `workspace_id` as the event's scope.** `crates/gyre-server/src/api/search.rs` `search_handler` records the event with `.with_scope(..., params.workspace_id.as_deref().map(Id::new), ...)` and the handler has no `AuthenticatedAgent` and no existence/tenant check on that query param — any authenticated caller can attribute `search.query` events to arbitrary (even nonexistent) workspace ids, polluting those workspaces' filtered analytics results. This is exactly the flaw class the candidate fixed on POST /analytics/events in commit `ad7d3e33a` ("persisting a caller-forged value would pollute another scope's filtered results") and the repo invariant behind `check-forged-scope-fields.sh` (the script only misses it because the field arrives as a Query param, not `req.`, and the handler lacks the auth extractor). Repro: `GET /api/v1/search?q=x&workspace_id=ws-victim` as any authenticated caller, then `GET /api/v1/analytics/events?event_name=search.query&workspace_id=ws-victim` returns the forged event. Repair: validate the workspace against the caller (add `AuthenticatedAgent` + `validate_workspace_scope`, as in the record handler) or drop the workspace scope from the event.
- [ ] **F3 (moderate, missing emission): remaining agent-death paths record no `agent.failed`.** `signal_chain.rs` `teardown_failed_spawn` (~line 1238: agent → `Failed` after a failed launch), `api/orchestrator.rs` process-death monitor (~line 408: orchestrator agent → `Dead` when its process dies), and `api/agents.rs` `update_agent_status` (public PUT /agents/{id}/status accepts `"failed"`/`"dead"`/`"stopped"` with no analytics emission) all transition an agent to a terminal failed/dead state without the spec's "Agent fails or is killed" event, while the sibling paths (fail/stop/admin-kill/stale-abort/spec-reject/repo-archive/compose) all emit. Fold into the F1 repair round.
