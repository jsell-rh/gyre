## What the diff actually changes

- **Base state:** the SDK path had NO server-side §11 self-check. The old `explorer-agent.mjs` did a best-effort dry-run inside the script (MCP fetch, warnings to stderr / attached to the `view_query` message), and the old server handler forwarded `view_query` immediately, reading only `query`/`explanation` — warnings were dropped, no refinement, no cap. The native LlmPort path had the full inline self-check.
- **Candidate:** adds a real server-mediated §11 loop for the SDK path (`run_explorer_agent_sdk` → `run_sdk_subprocess_once` + loop): extract → `self_check_dry_run` → `actionable_dry_run_warnings` → refine (re-invoke subprocess with feedback as the next question, `status: "refining"` each turn) → cap at `MAX_REFINEMENT_TURNS = 3` → best version sent at cap. Extracts the native path's inline classification/dry-run/feedback logic into shared helpers (`self_check_dry_run`, `actionable_dry_run_warnings`, `is_actionable_warning`, `self_check_feedback`) — semantics byte-equivalent to the previous inline code (compared hunk-by-hunk). Splits the system prompt into `build_system_prompt_body()` + per-path workflow step 1 (SDK: "Call graph_summary to understand the codebase structure", spec §10 verbatim; native: pre-loaded-context variant). Adds `EXPLORER_SDK_DEFAULT_MODEL = "claude-sonnet-4-6"` via new `resolve_llm_model_with_default` (native path keeps the gemini default — correct, Vertex can't serve claude names). Fixes the real defect where `run_sdk_subprocess_once` re-resolved `GYRE_EXPLORER_SDK_PATH` with a CWD-relative default instead of spawning the dispatch site's validated canonical path; the canonical path is now threaded through. Rewrites the mjs history handling from a non-existent `messages` parameter (silently ignored by the SDK — history was dropped) to a `<conversation_history>` transcript prefix in the prompt.
