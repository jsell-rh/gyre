## Non-blocking observations (recorded for follow-up, outside this task's enumerated contract)

- The task enumerates the termination paths as `complete_agent`, `fail_agent`, and the stale-agent Dead transition; the candidate covers those plus MCP-complete and admin-kill. Other pre-existing terminal transitions do not call `end_session`: `stop_agent` (Stopped), compose teardown (Dead), the orchestrator process-death monitor (Dead), `gate_executor`/`signal_chain` teardown_failed_spawn (Failed), and ralph_loop's iteration-ceiling / respawn-retry-exhaustion Failed transitions. In the normal Ralph flow the session is already ended by `complete_agent` before those run, and commit attribution is unaffected (a dangling open session has no later commits), but a session open at one of those terminations keeps `ended_at`/dirty unrecorded. Follow-up task material, not a defect against this task's contract.
- `relaunch_agent_session` starts the session before the launch attempt; a failed launch retried by `respawn_with_retry` stacks open sessions (newest wins attribution, so no mis-attribution, but the older stays open).
- Stored JSON columns (`files_changed`, `uncommitted_paths`, `messages_read`) deserialize with `unwrap_or_default()` on corrupt rows — matches the existing adapter convention; not a security decision signal.
- Within a single session, same-second commit ties in `find_by_session` order by the random-UUID id (no durable signal exists for that case; the cross-session lifecycle view does have the session-window tiebreak).
