## Verified against the task contract

- **Deliverable 1 — version discrimination.** `get_meta_spec_blast_radius` (api/meta_specs.rs) takes `?from_version=&to_version=`; `from_version` is the superseded version, defaulted to the registry's current version; `to_version <= from_version` is a 400 (`ApiError::InvalidInput`, verified to map to `StatusCode::BAD_REQUEST`). Per-workspace binding evaluation collects spec-level `meta_spec_bindings` pins (joined to the ledger entry's workspace scope) and required-flag visibility (Global/Tenant/Workspace at registry current). A workspace is affected only when a pin or the required flag resolves at the superseded version; otherwise it lands in `skipped_workspaces` with its pinned version and is excluded from every count/total — the spec's "internal-tools on v2, not affected" case. Both `expect()` sites in the skipped/affected label selection are unreachable-panic-safe (each is guarded by the branch condition that made the value `Some`).
- **Deliverable 2 — per-repo counts from real provenance.** `blast_radius_repo_provenance` queries three real storage surfaces per repo: agent-commit provenance (`agent_commits.find_by_repo`) joined to the author agent's spawn-time prompt-set record (kv `agent_meta_spec_sets`, via `load_prompt_set_record` with a per-request cache), chain attestations (`chain_attestations.find_by_repo` — commit SHA from the attestation output, spec identity from the signed input's `spec_path`, governing versions from the author's prompt record), and merge attestation bundles (`merge_requests.list_by_repo` + `attestation_store.find_by_mr_id` — the bundle's own `meta_specs_used`, merge commit SHA, MR spec ref). Counts are distinct spec identities / distinct commit SHAs (HashSets, deduplicated across surfaces) whose recorded `(meta_spec_id, version)` includes the superseded version. A repo with no matching provenance carries zero counts in the flat `affected_repos` and is omitted from the workspace's repos-with-work list and from `totals`. Nothing is derived from workspace repo membership.
- **Deliverable 3 — §8 labels preserved.** `workspace_binding` for own spec-level pins and Workspace-scoped required flags; `tenant_inheritance` for Global/Tenant-scoped required flags (`required_binding_reason`), with granular `binding` kinds (`required_global`/`required_tenant`/`required_workspace`/`spec_binding`); own bindings win the label when both surfaces bind. The pre-existing visibility test was updated to the new field shape with no weakened assertions.
- **Deliverable 4 — read-only + ABAC.** The handler performs only reads; route registration and the ABAC resolver entry are unchanged from the base (`abac_middleware.rs` maps `/api/v1/meta-specs/:path/blast-radius`).
- **Round-1 finding repaired.** `508a821b` seeds the `ws-br-dc-own` workspace row via `make_workspace_in_tenant` before `require_for_ws` — verified present in the candidate; the handler resolves Workspace-scoped required flags by matching `scope_id` against `workspaces.list()`, so with the row present the affected/id/reason/binding/pinned assertions match the traced handler logic.
