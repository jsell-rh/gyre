## Non-blocking observations (recorded for completeness, no repair required)

- `try_it_handler`'s container-dispatch path propagates a `dispatch_agent_launch` Err via `?` (reachable only for the SSH container-mode agent-name rejection; preview agent names are plain hex so it is effectively unreachable) without immediate teardown — the durable provisioning row, peer, and budget slot are reclaimed by the TTL expiry pass (the row is deliberately created before dispatch so the GC reclaims half-provisioned envs), recorded as `expired` rather than `failed`. Eventual, honest, self-healing.
- Local-mode preview ports are a deterministic hash of the env id into 18000–18999; two concurrent local environments can collide, in which case the loser's `preview-serve` fails to bind and the liveness GC records an honest `failed`. Container targets give each env its own network namespace, so the collision class is local-mode only.
- A concurrent DELETE + GC pass on the same environment could double-decrement the workspace's active-agent admission counter (both snapshots see a live env). Worst case is slight admission under-count, not scope or durability.
- Cross-workspace-home live updates depend on the shared connection's workspace subscription (the server only delivers workspace-scoped bus messages to subscribed members); with no workspace selected the cross-workspace timeline falls back to its fetched page. This matches the "delivered for the subscribed workspace" contract; the primary AC is the open workspace W's sidebar.
