## Non-blocking observations (recorded, not findings)

- Live-vs-fetched dedupe boundary: live entries key by bus message `id`, fetched `/activity` entries (which carry no `id` field) by the `(event_type, entity, timestamp)` tuple, so a live-delivered event re-fetched at the reconnect boundary (`created_at >= since`) can render twice. Cosmetic edge case; the task's "dedupe by id" requirement is implemented and the dominant reconnect window (entries emitted while offline) is fetch-only, hence duplicate-free.
- `try_it_handler` returns 201 CREATED even when dispatch failed; the failure is represented honestly in the body (`status: "failed"`, `end_reason`), the durable row, and a `preview.failed` event, and the UI renders "Preview failed / Try again". API-shape wart only.
- `web/dist` is not part of the base→candidate diff (matches the upstream bundle) — generated output is verifier-owned by assignment; not a finding.
