## Finding (blocking)

- [-] **F1 (code + test): registry approval payload case mismatch — CLI persona approval 400s, and the task's own deferred end-to-end test fails against the real server.** `GyreClient::approve_persona` (crates/gyre-cli/src/client.rs:2046) PUTs `{"approval_status": "approved"}` (lowercase) to `PUT /api/v1/meta-specs/:id`. The server parses that field case-sensitively (`parse_approval_status`, api/meta_specs.rs:8339 → `MetaSpecApprovalStatus::parse`, gyre-domain/src/meta_spec.rs:113-121 — exact "Pending"/"Approved"/"Rejected" only) and returns `400 Bad Request: invalid approval_status 'approved'`. Because `authorize_registry_write` runs before the parse, the admin-token CLI bootstrap reaches the parse on every fresh run (create → approve) and on resume-with-Pending: step 5 aborts with `step.fail`, so `gyre bootstrap` no longer converges — the CLI consumer the task explicitly required to keep working against the registry surface is broken. The same lowercase payload appears in `registry_meta_persona_is_spawn_bindable` (api/spawn.rs:10054), which asserts `StatusCode::OK` on that PUT running as the Admin-bypass system principal — the test will fail in the verifier (it was deferred, so the mismatch was never exercised in-sandbox; the CLI bootstrap tests run against a mock HTTP server and cannot catch payload mismatches). `persona_approval_via_registry_denies_agent` (abac_middleware.rs:7417) uses the same invalid payload but passes only because the write-gate 403 precedes the parse — latent, not caught. The web UI sends the capitalized form and is unaffected. Reproduce: `PUT /api/v1/meta-specs/<id>` with body `{"approval_status":"approved"}` as a tenant Admin → 400; with `"Approved"` → 200. Repair: send `"Approved"` from the CLI (and fix the two test payloads), or make `parse_approval_status` case-insensitive at the API edge the way `parse_kind`/`parse_scope` already are — either side is acceptable, but CLI, server tests, and server parser must agree, and a CLI-against-real-server (or exact-payload server) test should pin it.
