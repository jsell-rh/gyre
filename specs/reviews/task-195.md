### Verified working

- **Selection is real and pure.** `manifest_gates_for_mr(Option<&SpecManifest>, Option<&str>) -> Vec<ManifestGateSpec>` resolves the manifest entry whose normalized path matches the MR's `spec_ref` path (`specs/`-prefix and bare-path normalization), carries `persona` / `min_attestation_level` (default 1) / `stack_hash`, dedupes repeated personas (first wins), and returns empty for no manifest / no spec_ref / no match / no gates. Directly unit-tested (`manifest_gates_resolved_from_spec_ref`, `manifest_gates_empty_for_missing_inputs`, `manifest_gates_dedupe_repeated_persona`, `manifest_gates_match_bare_path_spec_ref_without_sha`).
- **Sourcing is real storage access.** `resolve_manifest_gates_for_mr` loads the MR (`state.merge_requests.find_by_id`), the repo (`state.repos.find_by_id`), and reads `specs/manifest.yaml` via task-193's `read_manifest` — no second reader. Reading at repo **HEAD** instead of the embedded SHA is correct and allowed by the task plan: `current_sha` in the ledger is the spec file's *blob* SHA (`get_blob_sha` → `git rev-parse <commit>:<path>`), which is not a treeish and cannot address the manifest; task-194's lifecycle path likewise reads the manifest at the pushed HEAD.
- **Union, not replace; no double-spawn.** `trigger_gates_for_mr` keeps every repo-level gate except those whose persona is covered by a manifest gate, and runs each manifest gate once. Manifest-wins on persona overlap is the right tie-break (the manifest gate carries the attestation constraints; skipping it would let a no-command repo-level AgentReview gate auto-pass). Tested in `trigger_gates_manifest_gate_wins_over_repo_gate_for_same_persona`; re-enqueue reuse in `trigger_gates_reuses_running_gate_agent_on_reenqueue`; no-spec-ref and no-manifest regressions covered by `trigger_gates_no_spec_ref_runs_repo_gates_only` / `trigger_gates_repo_without_manifest_runs_repo_gates_only`.
- **No parallel results table.** Manifest gates materialize as `AgentReview` `QualityGate`s with deterministic ids (`manifest-gate:<repo>:<spec_path>:<persona>`) and ordinary `GateResult` rows; `check_gates_for_mr` (gate_executor.rs:2316) defaults unknown gate ids to `required = true`, so pending/failed manifest gates hold and block the merge (`trigger_gates_failed_manifest_gate_blocks_merge` asserts the error names the manifest gate).
- **Real persona path, never the auto-pass stub.** `run_agent_review_gate` routes `command: None` + constraints to `run_persona_review_gate`, which passes only on an `Approved` review from an agent whose recorded persona matches, whose derived workload-attestation level ≥ `min_attestation_level`, and whose stack fingerprint matches a pinned `stack_hash` exactly (`check_reviewer_attestation`; levels via the same `derive_attestation_level` task-193 uses — no invented levels). Latest-verdict-per-reviewer with approval-wins; a persona agent's final `ChangesRequested` fails fast; otherwise the gate polls to its timeout and **fails closed**. `persona_gate_fails_without_qualifying_review` (timeout 0, no reviews) kills any regression to the legacy stub.
- **The forge actually spawns the gate agents (§16's core sentence).** `spawn_manifest_gate_agent` creates a real `Agent` record (`gate-<persona>-<mr-id>`, workspace-scoped, Active), writes the persona to the `agent_personas` KV namespace (its production writer besides validated spawn), mints a `review:submit`-scoped EdDSA JWT (mint/registration failure fails the spawn closed — no unscoped fallback), dispatches a `ReviewRequest` message carrying `{mr_id, repo_id, spec_path, spec_ref, persona, min_attestation_level, stack_hash}`, and launches the agent's runtime process through the platform's shared compute-target machinery (`api::spawn::launch_agent_workload` — the extracted four-backend dispatch `spawn_agent_core` itself uses), with the token in `GYRE_AUTH_TOKEN` and a workload attestation recorded at launch (so the agent's own reviews derive at level ≥ 1). Teardown kills the runtime via the backend that owns the handle (`spawned_backends` routing), removes the registry entries, revokes the token with an audit event, and Stops the record (kept for attribution).
