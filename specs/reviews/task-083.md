### Findings

- [open] **F1 (major): workspace-home Specs section is not scoped to the selected workspace — the §2 data-scoping requirement is unmet and the server ignores the query the client relies on.** Task Required Behavior #2: "Decisions, Specs, Architecture, Repos, Briefing, and Agent Rules use the selected workspace's real data." The client calls `api.specsForWorkspace(workspace.id)` (sends `?workspace_id=`), but `GET /api/v1/specs` does not parse `workspace_id` at all — `ListSpecsQuery` (`crates/gyre-server/src/api/specs.rs:154`) has only `kind: Option<String>` and the handler returns `spec_ledger.list_all()` unscoped. The client does not compensate: `filteredSpecs` (`web/src/components/WorkspaceHome.svelte:427`) filters only by status, so the §2 Specs table renders every ledger spec regardless of the selected workspace (unlike `loadDecisions`, which filters notifications on `n.workspace_id === workspace.id`). Probe (temporary test in specs.rs, reverted; source in evidence): seeded specs with `workspace_id` ws-a and ws-b, `GET /api/v1/specs?workspace_id=ws-a` returned **both** `system/a.md` and `system/b.md`. Consequences: (a) §2 violated — workspace A's home shows workspace B's (and any) specs, a cross-workscope/cross-tenant info-disclosure surface; (b) §10 violated — the `/all` Specs section (`specsForWorkspace(null)`, same endpoint) shows specs from workspaces the caller cannot access, while §10 scopes the section to "workspaces the caller can access"; (c) the Shipped claim "every section loader in WorkspaceHome.svelte queries with the selected workspace's id" is technically true but behaviorally hollow for Specs — the query argument is a server-side no-op, which is exactly the claim-vs-reality gap the umbrella goal prohibits. The existing tests cannot catch this: they mock `specsForWorkspace` to return pre-scoped data and assert only the call argument (mirrored logic). Remedy: honor `workspace_id` in `list_specs` (filter ledger rows by their workspace_id, or by the workspace's repos), or filter client-side on `workspace_id`/`repo_id` as Decisions does; scope the `/all` Specs list to the caller's accessible workspaces; add a regression test with real scoping semantics (mixed-workspace ledger rows must not all render).
- [open] **F2 (minor, cosmetic): Agent Rules version badge class mismatch.** `WorkspaceHome.svelte:1686` renders `<span class="rule-version">` while the CSS added in this change defines `.rules-version` (`WorkspaceHome.svelte:5716`); the badge renders unstyled. Rename one side.
