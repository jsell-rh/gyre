### Verified working (no findings)

- **Newest-1000 window (deviation 1) is correctly implemented.** ws.rs:151-230: fetch the newest `REPLAY_LIMIT+1` (1001) qualifying messages per subscribed workspace (both adapters return newest-first with composite `(created_at DESC, id DESC)` order and apply the limit after the order — mem.rs:4944-4981, sqlite/message.rs:325-378), merge the pools, sort by the same composite key, `drain(1000..)` when `pool.len() > 1000`, reverse, deliver oldest-first. Soundness of the per-workspace 1001 fetch: the combined newest-1000 window draws at most 1000 messages from any single workspace, and truncation detection via `pool.len() > 1000` is exact in all cases (if total qualifying ≤ 1000 every pool is exact; if > 1000 the pool exceeds 1000) — confirmed by the randomized oracle, not just inspection. The old handler's oldest-1000-of-newest-1001 window and de-facto per-workspace cap are both gone.
- **Truncation signal is exact.** Single production emission site (ws.rs:228), gated on `truncated`, sent once after the window; never at ≤1000 (old code also only signaled on cap-hit, but the new detection is total-based, not first-workspace-break-based).
- **Strictly-greater boundary (deviation 2) via call-site shift.** ws.rs:159-175: `since_ms = last_seen.saturating_add(1)` — for integer epoch milliseconds `created_at >= last_seen+1 ⇔ created_at > last_seen`. The task explicitly allows either adapter-level or call-site enforcement; the call-site choice preserves the documented inclusive REST `since` semantics of `GET /api/v1/workspaces/:id/messages` (api/messages.rs:487-494, unchanged, passes `params.since` straight through) and keeps both adapters untouched and in agreement (mem-port-contracts invariant preserved by construction: mem and SQLite/Postgres see the identical shifted bound). Re-delivery of a message created exactly at last_seen is gone; a message 1 ms later still qualifies.
- **Tests are real and mutation-sensitive.** The four in-crate tests (ws.rs:1015-1290) drive a real loopback WebSocket (`start_test_server`, port 0) against the mem AppState, and the SQLite test (tests/message_persistence.rs:644-876) drives the real router over `build_state` with `GYRE_DATABASE_URL` set — the production Diesel adapter path (task-247 `store!` wiring), not a mock.
