## Findings

- [**F1 (major) — BudgetExhausted is never delivered to agent inboxes; the specced graceful stop cannot function.**] `crates/gyre-server/src/api/budget.rs` lines 641 and 680: both the 100% graceful-stop path and the beyond-limit path emit each per-agent `BudgetExhausted` message to `Destination::Workspace(workspace)`. Every agent-facing inbox surface returns only `Destination::Agent(<id>)` messages: `GET /api/v1/agents/:id/messages` (`api/messages.rs` → `list_unacked`/`list_after`), the MCP inbox tool (`mcp.rs` ~2217), and both adapters (`mem.rs` 3783/3811 filter `Destination::Agent(id) == agent_id`; `sqlite/message.rs` `to_type='agent' AND to_id=...`). `emit_event` only persists + WS-broadcasts (agents don't use WS; `ws.rs:437`), and the dispatch channel is a no-op drain (`lib.rs:1360`). The established pattern for informing an agent is `Destination::Agent(agent_id)` (`constraint_check.rs:1603`, `ralph_loop.rs:307`, `merge_processor.rs:324`). Spec `agent-runtime.md` line 418: "All active agents in the workspace receive a `BudgetExhausted` message in their inbox. Agents have 60 seconds to commit current work and call `agent.complete`." Since agents cannot learn about exhaustion, the 60s grace degrades to a delayed hard kill — acceptance criterion "100% threshold: BudgetExhausted messages + 60s grace + kill" is only 2/3 met. The covering test `exhaustion_emits_messages_and_kills_after_grace` asserts the message via `messages.list_by_workspace` — a stream agents never read — so it passes while the inbox delivery requirement is absent (self-confirming for that leg). **Repair:** emit `Destination::Agent(agent.id.clone())` per active agent (optionally in addition to the workspace event) and assert delivery through `list_unacked(&agent_id, ...)`.
- [**F2 (moderate) — repo budget override fields accepted and validated but never enforced.**] `PUT /api/v1/repos/:id` (`api/repos.rs:298-343`) accepts `budget.max_concurrent_agents` and `budget.max_agent_lifetime_secs` and 400-validates them against the workspace budget, but the only consumer of `repo.budget` is `check_repo_spawn_budget` (`api/budget.rs:329`), which reads only `max_tokens_per_day` and `max_cost_per_day`. A repo budget override with `max_concurrent_agents: 1` has no effect anywhere — dead config with the appearance of enforcement (workspace-level `max_concurrent_agents` *is* enforced via `check_spawn_budget`, so the asymmetry is visible). **Repair:** either enforce repo `max_concurrent_agents` in `check_repo_spawn_budget` (count Active agents scoped to the repo, as `signal_chain.rs` does for `Repository.max_agents`) or stop accepting the field.
- [**F3 (minor, spec-fidelity) — BudgetWarning notification priority contradicts two specs, neither amended.**] `agent-runtime.md` §4 (line 417) and `human-system-interface.md` (lines 242, 308) both specify Inbox priority 7 for BudgetWarning; the implementation uses `NotificationType::AgentBudgetWarning` default rank 4 / High per `user-management.md` §Notification Entity. The conflict is documented in the task file's "Notes for review", but per the goal's rule 4 the spec should have been reconciled through the spec lifecycle rather than reinterpreted in code comments. Repair: amend agent-runtime.md/HSI (or user-management.md) so the three agree, in the revision commit.
- [**F4 (minor) — `system://persona` serves mislabeled content.**] `mcp.rs` `prompt_persona` returns `rendered_prompt`, which spawn.rs builds as `render_system_prompt(...) + "\n" + render_protocol_prompt()` — persona + protocol concatenated — while the prompt's description calls it "the assembled meta-spec prompt set". The content is real and pinned, but a client asking for persona also gets the protocol section verbatim. Cosmetic; fix by storing/serving the persona section separately or correcting the description.
