## Minor observations (non-blocking, recorded for completeness)

- Enforcement evaluates workspace-level utilization only; a tenant-level (`tenant:global`) limit crossing does not trigger actions. This matches the task plan (the helper is defined over `workspace_id`) and the acceptance criteria, and is honestly disclosed in the coverage row. If the platform later wants tenant-level kills, that is new work, not a defect of this task.
- `create_budget_reassignment_task` falls back to `repo_id = Id::new("")` when the killed agent has no repo. Not a scope-identity fabrication (tenant/workspace are derived from the agent record), but an empty repo id is a wart; real budget-killed agents almost always carry a repo.
- Tiny race window between marker load and save could double-emit one threshold crossing under concurrent recordings in the same instant; per-period de-dup is otherwise sound and persisted.
