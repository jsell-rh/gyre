Findings:

- [-] **F1' (major, carried from review f7631cfb — unfixed): Kubernetes Pods cannot start in the standard flow.** The kubernetes dispatch arm (spawn.rs ~1025-1075) passes `&spawn_config` whose `work_dir` is the canonicalized server-local worktree path (the worktree is created on the server before dispatch, so it exists whenever the repo has commits), and `build_pod_manifest` (kubernetes.rs:149) writes it into `spec.containers[0].workingDir` with NO volumes in the manifest. The agent image contains no such path (entrypoint clones into `/workspace/repo`; image WorkingDir `/workspace`), so under CRI the container fails to start (runc chdir ENOENT). The SSH-docker arm overrides `work_dir` to `/workspace` for exactly this reason (spawn.rs:938-947); the k8s arm lacks the same override. Reproduced at this candidate by probe (real spawn path, stub `kubectl` capturing the applied manifest): `workingDir=/tmp/gyre-unit-test-repos-.../wt-repo.git/worktrees/feat-probe`, `volumes=null` (evidence: `k8s-workingdir-probe.txt`; temporary probe test removed, source restored and hash-verified). "Kubernetes backend creates/manages Pods" is met only nominally — Pods are applied but agents cannot run when a worktree exists, which is the standard flow; coverage row 24 overstates. Fix: mirror the SSH arm (k8s SpawnConfig with `work_dir: "/workspace"`) or mount the worktree via a cluster-visible volume.
- [-] **F2' (major, carried from review f7631cfb — unfixed): Nix build is not reproducible — `flake.lock` is not committed.** Spec §3 Nix-Based Image Build lists `flake.lock # Pinned dependencies` in the required tree and (still, after this round's amendment) states "The Nix flake pins all dependencies ... for bit-reproducible builds". The candidate commits `flake.nix` but no `flake.lock` (`git ls-files docker/gyre-agent/`), and `inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.11"` is a moving branch reference — the flake's own comment concedes the lock is only "created on first run". Two builds at different times resolve different nixpkgs revisions and produce different images, so the acceptance criterion "Nix flake for reproducible agent image builds" is only nominally met and `wl_image_hash` attestations are not stable across rebuilds; coverage row 25's "pinned nixpkgs" claim is false as shipped. Fix: generate and commit `flake.lock` (or pin the input to a specific revision).
- [-] **F3' (minor, docs; carried from review f7631cfb — unfixed): `docs/api-reference.md` admin table broken by the inserted tenant-scoped block.** The "Workspace selection ..." prose paragraph (ending with a stray ` |`, ~line 281) is followed directly — no blank line, no header/delimiter row — by the `/api/v1/admin/bcp/targets`, `/api/v1/admin/bcp/drill`, and `/scim/v2/ServiceProviderConfig` rows, which therefore render as paragraph continuation text rather than table rows (they were valid rows of the admin table before this diff). Fix: blank line after the paragraph (and drop the stray ` |`), or move the block below the table.
