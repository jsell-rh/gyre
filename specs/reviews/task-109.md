- **F1 (major): the committed `web/dist` at the candidate does not contain the Spec Lifecycle UI, and the shipped notes' claim that the rebase merge rebuilt it is false.** Reproduce: `git grep -c "spec-lifecycle" HEAD -- web/dist/` → no matches (also `spec_lifecycle`, `watched_paths`, `default_priority_new` — zero occurrences in every `web/dist/assets/*.js` at HEAD); the last commit touching `web/dist` is the base-side `0ceffb69d` "build(web): regenerate verified assets (task-088)". The rebase merge `76b54d4fa` ("Merge commit 'c5deca801…'") resolved the `web/dist` conflict by taking the base's bundle wholesale: `git diff --stat c5deca801 76b54d4fa -- web/dist` is **empty** (byte-identical to the base's dist), while the pre-merge task-109 commit `c8936f051` carried a correct bundle (`index-DlzAFB6w.js` contains the spec-lifecycle strings) that the merge discarded. The shipped notes state the conflicts were "resolved by rebuilding `web/dist` from the merged source" — a rebuild of merged source (which contains task-109's `RepoSettings.svelte`) cannot be byte-identical to the base's pre-task-109 bundle; the artifact contradicts the claim. Impact: `gyre-server/src/spa.rs` embeds `web/dist` via `rust_embed` at compile time, so the documented `SKIP_WEB_BUILD=1` build mode (AGENTS.md: "uses committed web/dist/") serves an SPA without the Spec Lifecycle settings tab — the acceptance criterion "UI shows and edits spec lifecycle settings" fails in that mode. Every prior UI task in this repo ships a "build(web): regenerate verified assets (task-XXX)" commit; this candidate has none at HEAD. Remedy: rebuild `web/dist` from the merged source and commit it (the bundle must contain the spec-lifecycle testids/locale keys), correcting the shipped notes.
- **F2 (moderate): false test-evidence claim in the shipped notes — the server API tests are mem-backed, not "SQLite-backed".** The notes say the 5 API tests "construct a fresh SQLite-backed server, so GET/PUT exercise the migration end-to-end". The API-over-SQLite path is untested, and the evidence claim as written is inaccurate — reviewers and the verifier must be able to trust shipped test claims.
