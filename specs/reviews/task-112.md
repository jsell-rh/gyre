## Findings

- [open] **F1 (major): `NotificationChannels` shape change breaks already-persisted `users.preferences` — adapter suite red, silent preference reset on upgrade.** The candidate rewrote `NotificationChannels` from the flat `email_enabled`/`email_digest` shape to the spec's nested `email`/`webhook`/`slack` shape (correct per §Delivery Channels) but shipped no data migration and no serde compatibility for the old JSON already stored in `users.preferences` by base code — including the `2026-10-08-000058_user_entity_profile_fields` backfill literal, which still serializes the old shape. Reproduction: `cargo test -p gyre-adapters --lib` → **392 passed, 1 FAILED** (`sqlite::tests::migration_000058_backfills_unique_url_safe_usernames`, panic at `crates/gyre-adapters/src/sqlite/mod.rs:489`: migration literal `..."notification_channels":{"in_app":true,"email_enabled":false,"email_digest":"Off"}...` vs new `UserPreferences::default()` `..."notification_channels":{"in_app":true,"email":{"enabled":false,...},"webhook":null,"slack":null}...`). The candidate touched neither that test nor migration 000058, so the failure is attributable solely to the domain shape change. Production impact beyond the test: the SQLite and Postgres user read paths (`sqlite/user.rs:46-51`, `postgres/user.rs:46-51`) deserialize with `.ok().unwrap_or_default()`, so every pre-existing preferences row fails `UserPreferences` deserialization (missing non-Option `email` field) and is silently reset to defaults — user-customized theme, ui_density, code_font_size, diff_view, activity_feed_scope, and default_workspace_id are lost on upgrade, and the reset is persisted on the next update. This also falsifies the task's acceptance criterion "cargo test --all passes"; the implementer's recorded evidence listed no `gyre-adapters` run. **Repair:** append migration `000060` (next unused sequence, portable SQLite/PG SQL — plain string functions or no-op-if-new-shape guard) rewriting stored `users.preferences` JSON from the old `notification_channels` shape to the new one, or make the domain type deserialize both shapes (serde alias/default compat) and re-serialize on write; update the 000058 test expectation to the chosen strategy and add an old-shape-row upgrade test. Acceptance: `cargo test -p gyre-adapters --lib` green with the old-shape → new-shape cutover proven.
