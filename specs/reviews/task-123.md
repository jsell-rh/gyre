## Verified working

- **Entity model: PASS.** `Notification` (gyre-common/src/notification.rs) carries every spec field — id, user_id, notification_type, title, body, `source` (`NotificationSource` {entity_type, entity_id, workspace_id, repo_id}), `priority` (`NotificationPriority` Low/Medium/High/Urgent), action_url, read, read_at, created_at — plus the HSI §2 inbox fields (workspace_id, priority_rank, resolved_at, dismissed_at, tenant_id) the HSI contracts require. All 18 taxonomy variants defined and round-tripped. The two priority models are kept consistent by construction: the four-level priority is always the band of the HSI 1–10 rank (`from_rank`), and the band test pins the spec's own level examples (Low=MrMerged/GatePassed, Medium=DependencyStale/SpecDriftDetected, High=AgentBudgetWarning/GateFailure, Urgent=SecurityFinding/AgentEscalation/MrReverted).
- **Backward compatibility: PASS.** `parse()` accepts the pre-rename DB strings (`SpecPendingApproval`, `BudgetWarning`); the HSI spec carries a supersession note (spec amended, not contradicted). Pre-000059 rows map NULL `entity_type` to the generic "system" kind rather than fabricating a source.
- **Persistence: PASS.** Migration 000059 (next unused sequence after 000058; portable SQL; down.sql provided) adds entity_type/action_url/read/read_at and backfills read state from resolved/dismissed timestamps. New port methods `mark_read` (user-scoped, stamps/clears read_at) and `has_active_notification` (dedup) are implemented in SQLite, PostgreSQL, and mem adapters with the same semantics; retention now treats marked-read as read. Adapter tests run the real migration on SQLite.
- **Creation paths: PASS.** Every stand-in/mis-typing the task called out is fixed in production code: MrMerged (was SuggestedSpecLink), AgentFailed (was AgentEscalation), SpecApprovalRequested (rename), BreakingChangeDetected (was CrossWorkspaceSpecChange), SpecDriftDetected (was GateFailure, rank-3 override kept), InvitationReceived (was TrustSuggestion). ## Observations (non-blocking)

- `notify_gate_passed` falls back to `user_id = author_agent_id` when the agent has no `spawned_by`, producing a dead-letter notification owned by an agent id. This mirrors the pre-existing `notify_gate_failure` behavior exactly; consistent, not a regression.
- `NotificationSource.entity_type` values in use include kinds beyond the spec's comment examples ("repo", "persona", "task" alongside "agent"/"mr"/"spec"/"gate"/"budget"/"workspace"/"system"). The spec field is an open `String` with examples, not a closed enum, and `deep_link` routes unknown kinds to the workspace home, so this is a doc-comment nicety, not a contract violation. The doc comment in gyre-common could be updated to list them all.
- `specs_assist::save_spec` types the SpecApprovalRequested source as "mr" (the approval MR) rather than "spec"; the deep link targets the MR, which is where approval happens. Defensible reading of "source".
- PostgreSQL adapter is untested in this sandbox (no PG available); it mirrors the SQLite implementation field-for-field, and migration SQL is portable by construction (mechanical check + SQLite runs the same embedded dir).
