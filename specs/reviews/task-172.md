Findings (details with reproduce commands in `/tmp/stage/review-evidence/`):

- **F1 (major, code)**: `runPreview`'s spec context calls `api.thoroughPreview` → `POST /repos/:id/graph/thorough-preview`, a route that does not exist anywhere in `crates/gyre-server` (only `/graph/predict|diff|link|...` are registered; `ExplorerView.svelte:423` already treats this endpoint as not existing). In production every spec-context Preview rejects with the request() 404 error, and the catch block calls `finishPreview()` → `previewState = 'preview_complete'`. Probe with the exact 404 rejection: the **Iterate button renders** — a failed preview presents §9 State 3 "Preview Complete". Same fabricated completion on every other failure path (previewPersona catch, 30 s/300 s timeouts, poll catch). Fix: failure must return to editing or fall back to the fast `graphPredict` prediction (the ExplorerView pattern), never `finishPreview()`.
- **F2 (major, code)**: Esc double-fire. EditorSplit's `<svelte:window onkeydown>` Escape handler calls `preventDefault()` but not `stopPropagation()`; DetailPanel's panel div has its own Escape handler (`onback()`/`close()`, DetailPanel.svelte:2037). With focus inside the panel (the normal case — the user is editing), one Esc closes the EditorSplit **and** pops detail history / closes the panel / `window.history.back()` in repo full-page mode (App.svelte:1624 wires `onback={() => window.history.back()}`). Probe: bubbling Escape from the textarea → `onback-calls: 1`. Violates the AC "Back/Esc returns to normal detail panel view". The shipped DetailPanel Esc test fires on `window` only, which cannot reach the div handler — the suite is structurally blind to this.
- **F3 (moderate, code)**: Esc with the 409 conflict dialog open dismisses the dialog **and** fires EditorSplit's `onClose` (probe: `onClose-called: 1`) — SpecConflictDialog's own window keydown handler doesn't suppress the parent's. The expanded panel collapses, discarding the editor context, on the keypress that was only meant to close the dialog.
- **F4 (major, code)**: The meta-spec context parses `architecture_diff`/`specs_diff` — fields the server never sends. `PreviewResponse`/`PreviewStatusResponse` (meta_specs.rs:161-177) carry only `preview_id, state, specs, blast_radius, structural_impact`. Probe feeding the exact real struct shape: after a "complete" preview the Code Diff tab shows "No code diff available for this preview." and the Architecture pane has zero overlays — both right-panel tabs are permanently empty in production, and the fields the server *does* return (`blast_radius`, `structural_impact`) are ignored. The §9 State 3 requirement ("structural diff from the knowledge graph", "traditional line-level diff") is not producible by any current server response. All 37 tests pass because they mock synthetic shapes.
- **F5 (moderate, code)**: The meta-spec context is unreachable from the production UI: nothing passes `context="meta-spec"`/`targetSpecs`/`onpublish` — the production §9 surface (MetaSpecs.svelte, mounted from App.svelte) kept its own parallel implementation and does not mount EditorSplit. Probe: `editor-split-mounted: false, metaspecs-own-selector: true`. The task's "used by BOTH spec editing and meta-spec editing; build it as a reusable component" is satisfied only at the component level; the workspace now has two divergent §9 client implementations, and the Shipped text does not disclose that the meta-spec half has zero production callers.
- **F6 (minor, code)**: The locked editor during `preview_running` classifies `content.split('\n')` lines by leading `+`/`-` as add/remove — but `content` is the markdown draft, not a diff. Markdown bullet lines starting with `-` render struck-through red during §9 State 2, misrepresenting the draft.
- **F7 (spec/process)**: The Shipped text claims "markdown textarea with toolbar" — no toolbar exists in the component (grep -i toolbar → nothing). ui-layout.md §2 line 247 requires "standard markdown editor with toolbar"; the task plan repeats it (lines 16, 31). Either implement it or correct the record.
- **F8 (test)**: The suite never exercises the paths a real deployment takes: thoroughPreview rejecting (404), previewPersona returning the real response struct, or Escape bubbling from inside the panel div. Given F1-F4, 66/66 green does not establish the preview ACs hold in production.

Notes for the revision round: the endpoint gaps (thorough-preview missing; meta-spec preview returning no diff payloads) are server-side facts outside this task's diff, but the component's failure handling is in-scope: a UI that renders "Preview Complete" with empty tabs after a 404 is a hollow-completion defect in the code this task shipped, and it is fixable client-side (honest failure state + fast-prediction fallback, rendering `blast_radius`/`structural_impact` for the meta-spec context) without waiting on server work. Esc fixes (F2/F3) are one-liners (`stopPropagation()` / dialog-open guard). TCP listener probes are unsupported in this sandbox; host verification should additionally run `cargo test -p gyre-server meta_spec` and the exact-head `web-build` CI job.
