Findings:

- **F1 (major, blocking): Esc no longer closes the EditorSplit pop-out — acceptance criterion "Back/Esc returns to normal view" is broken, and "Tests pass" is false.** `SpecConflictDialog.svelte`'s `<svelte:window onkeydown>` registers unconditionally (even with `conflict === null`, dialog closed). The candidate's rewritten handler consumes every Escape (`e._escConsumed = true; e.preventDefault(); e.stopPropagation()`) with no open-dialog guard. `stopPropagation()` sets `event.cancelBubble`, and Svelte 5's `target_handler` wrapper (`svelte/src/internal/client/dom/elements/events.js`: `if (!event.cancelBubble) { handler(event) }`) then skips all later-registered `svelte:window` handlers — including EditorSplit's own Esc handler. `DetailPanel.svelte:5286` also mounts a SpecConflictDialog that registers before EditorSplit mounts, so in the pop-out context EditorSplit's Esc handler is always shadowed (proven: its debug `console.log` fires in the direct-render suite but not in the DetailPanel context; the committed debug test's own output shows `escConsumed=true`, `editor split still there: true`). Remedy: guard the dialog handler with `if (!conflict) return;` (only consume Esc while the dialog is actually open — which is what EditorSplit's `if (specConflict) return;` comment already assumes), and delete the debug artifacts below.
- **F2 (major, blocking): the committed served bundle entrypoint is corrupt.** `web/dist/index.html` at the candidate contains unresolved git merge-conflict markers (`<<<<<<< HEAD` / `=======` / `>>>>>>> b1cdb0dd`) referencing two different bundle sets, all tracked at HEAD. `web/dist/` is what gyre-server serves (SKIP_WEB_BUILD deployments): the shipped page renders conflict-marker text and loads the app twice. A fresh `vite build` from the candidate source produces exactly one clean bundle set, so the committed dist is not the build output of this source and the Shipped claim "vite build reproduces the committed dist byte-exactly" is false at this head. Remedy: rebuild dist from the fixed source (single bundle set, no markers) and commit that.
- **F3 (minor): leftover debug `console.log` in production code.** `EditorSplit.svelte` `handleKeydown`'s first line is `console.log('DEBUG EditorSplit.handleKeydown', e.key)` (commit `4b80b93b`, listed in the task's `commits:`). It fires on every keydown and ships in a fresh production bundle. Remove it.
- **F4 (minor): debug scratch test committed.** `web/src/__tests__/__debug-esc.test.js` (commit `4b80b93b`): 61 lines, zero assertions, only console.log diagnostics of F1. It matches the vitest include glob and runs in CI as assertionless test pollution. Remove it.
- **F5 (minor): 9 dead i18n keys.** `editor_split.md_{bold,italic,heading,list,code,link,quote,undo,redo}_aria` were added but never wired — `TOOLBAR_BUTTONS` sets no `aria` field, so toolbar buttons expose raw 'B'/'I' labels to screen readers. Either wire the aria labels onto the buttons or drop the keys; the Shipped "no missing or dead keys" claim is inaccurate as-is.
- **F6 (process): false completion evidence.** The Shipped section claims 66/66 passing suites and a byte-exact reproducible dist at this head; the actual state is 65/66 with a deterministic Esc failure and a corrupt committed dist. Under the task's "no fake completion" rule, ready-for-review with these claims is not supported by the candidate's actual state.
