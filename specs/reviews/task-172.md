## Verified working (no findings)

- **Reusable component, both production contexts.** `EditorSplit.svelte` implements the §2 two-pane layout once: left = markdown textarea + toolbar (bold/italic/heading/list/code/link/quote/undo/redo, each with localized aria-labels) + inline LLM chat; right = Architecture (default) + Code Diff tabs. DetailPanel mounts it (`context="spec"`) behind the Preview-button pop-out with Back/Esc (`closeEditorSplit`); the MetaSpecs workspace view (App.svelte `mode === 'agent_rules'`) mounts it (`context="meta-spec"`) with `targetSpecs`, `onpublish`, and `onPreviewStateChange` locking the persona selector while a preview runs (§9 State 2).
- **The parallel §9 client and its fake completion are genuinely gone.** git diff confirms MetaSpecs.svelte's `simulatePreview`/`isSimulatedPreview` fallback — which fabricated State 3 when `previewPersona` failed — is fully removed; the §9 loop runs through the shared EditorSplit, and a failed/unavailable/timed-out preview returns to editing with an error banner rendered in every right-pane state, never a fabricated complete state. Both honest-failure paths are pinned by tests (thoroughPreview-404, previewPersona-404).
- **State machine is real.** editing → preview_running (editor locked, per-spec progress, Cancel/Esc) → preview_complete (Iterate returns to editing with results retained) → iterate cycle covered by tests in both contexts; the meta-spec path drives the real `POST /workspaces/:id/meta-specs/preview` + status polling.
- **Wire shapes match the server, not synthetic mocks.** EditorSplit renders the exact `PreviewResponse`/`PreviewStatusResponse` fields (`preview_id`, `state`, `specs`, `blast_radius`, `structural_impact`) declared in `crates/gyre-server/src/api/meta_specs.rs:159-175`, and the tests feed those shapes. The LLM chat parser matches `specs_assist.rs`'s actual SSE format (`event: partial` → `{text}` chunks, `event: complete` → `{diff, explanation}` with add/remove/replace+path ops); `applyDiffOps` implements those ops.
- **Accept/Edit/Dismiss are correct and in-memory.** Accept applies the diff ops without saving (test asserts `specsSave` not called), Edit appends the suggested text for manual refinement, Dismiss leaves content untouched — matching §3 steps 4–6.
- **Optimistic concurrency is real, not decorative.** `baseSha` comes from the server-loaded `specDetail.current_sha` (DetailPanel:992), is sent as `base_sha` (pinned by test), a 409 opens the conflict dialog, Overwrite re-saves with `overwrite: true` (pinned), Discard takes the server content.
- **Esc semantics verified by mutation.** Single-Esc guard in DetailPanel is load-bearing and regression-tested (probe A); conflict-dialog Esc ownership is load-bearing and correct in production (probe B); Esc during a running preview cancels the preview rather than closing the split (test with `onClose` spy).

## Observations (non-blocking, recorded for follow-up)

- **O1 (test gap).** The `if (specConflict) return;` Esc guard in `EditorSplit.handleKeydown` — the mechanism behind the Shipped claim "While the 409 conflict dialog is open it owns Esc" — is not pinned by any committed test: removing it leaves the whole EditorSplit suite green (probe B). Production behavior is correct (verified independently), so this is a coverage gap, not a defect. A future test addition should assert: dialog open → Esc → dialog closed, split still open, `onClose` not called.
- **O2 (pre-existing backend gap, outside this task).** `api.thoroughPreview` calls `POST /repos/:id/graph/thorough-preview`, which has **no server route** — every real spec-context Preview returns an honest 404 error banner, so the spec context cannot reach Preview Complete in production (the meta-spec context can, via the real preview endpoint). This is pre-existing: base `e608ac78`'s ExplorerView already called the same missing route (with a prediction fallback), and ui-layout.md §2/system-explorer.md §3 frame the thorough Phase 2 preview as a complement to the shipped Phase 1 `graph/predict` fast preview. The candidate discloses the 404 truthfully and pins the honest-failure path; the Phase 2 backend belongs to a separate task and should not be closed by this review.
