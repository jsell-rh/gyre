## Findings (details in /tmp/stage/verdict.json)

1. **[blocking] Job-history cache fallback resurrects pruned runs** (`api/admin.rs:143-151`). `job_history_cleanup` prunes only the durable store; `GET /admin/jobs` then falls back to the in-memory ring whenever the durable list is empty and re-serves the deleted runs. For daily jobs the 50-entry ring spans >30 days, so the default retention prunes runs that the endpoint then resurrects — the cleanup's effect is invisible on the only admin surface, contradicting "the durable store authoritative". Only a durable read *error* (already handled loudly in `durable_history`) should fall back.
2. **[blocking] Perpetual refresh loop for the primary use case** (`secret_rotation.rs`). `expiring()` window (3600 s) equals Google's `expires_in` (3600, also the fabricated default when absent), so a GCP SA secret never leaves the window and is re-refreshed every 5-minute cycle forever. Tests use 5400/7200 and cannot catch it.
3. **Vault policy denial aborts agent resolution instead of scoping it** (`vault/mod.rs:769-810`). A 403 anywhere in the cascade fails the whole resolution; §7's "Vault policies scope the returned secrets" is only realized when the agent role can read the entire subtree (scoping then a no-op). Fail-closed, no leak — but the §7 property is undelivered and untested (stub accepts every path).
4. **Completed runs lost on persistence failure** (`jobs.rs:299-310`): record() error logged only; the run vanishes on restart with no retry or surfacing.
5. **Non-atomic delete+create rewrite of live credentials** (`secret_rotation.rs:390-397`, `api/oauth.rs:425-453`): crash window permanently loses an SA key / refresh token; concurrent resolution sees it missing.
6. **Audit tenant_id backfill joins only workspaces** (migration 000074): user-scoped legacy rows (auth events) stay NULL and vanish from every tenant-scoped admin view, though new identical events would be scoped via `users.tenant_id`.
7. **Maintenance/sweep gaps** (`maintenance_jobs.rs`): repos under `repos_root` without a DB row never maintained; SSH-backend orphans permanently unreapable and re-logged every 10-minute sweep forever; local restart-orphans killed by recorded pid without a liveness/identity check (PID-reuse hazard; failed kill treated as success in `compute/local.rs`).
8. **`kv_list` fails open on malformed 2xx** (`vault/mod.rs`): missing `/data/keys` silently yields an empty list (contrast `kv_read`, which errors).
9. **q-search case-folding mismatch** (`sqlite/audit.rs`, `postgres/audit.rs`): Unicode-aware SQL `LOWER()` vs ASCII-only Rust re-filter drops hits; diverges from the mem adapter.
10. **UI gaps vs contract wording** (`TenantSettings.svelte`): Server Logs tab has no `since` control though its own locale string advertises it; Audit tab renders only event_type + q, not the /audit/events filter set.

Minor (recorded, non-blocking): SOPS first-boot auto-identity generation race (concurrent first writes can orphan a secret's ciphertext — same class as the legacy auto-key); unknown `GYRE_SECRET_BACKEND` values silently fall back to sops instead of erroring (typo of "vault" serves from the DB); OAuth handler re-serializes from the lossy typed doc, silently stripping extra fields (GCP handler preserves them); `record_cycle` runs (merge_processor/stale_agent_detector/task_scheduler) persist empty logs; the pre-existing unscoped audit SSE stream is rendered next to the new tenant-scoped durable trail in the same Audit tab; per-run log lines have no size cap; `GET /admin/export` still reads the volatile TelemetryBuffer.
