## Findings

- [blocker] **F1 (code, `api/admin.rs`): `kill_agent` marks the durable instance record terminated even when the kill FAILED.** `kill_attempted` is set before the kill result is checked in both branches (in-memory ~546-557; restart-orphan ~612-618 — failures only `tracing::warn!`'d), and `mark_terminated(&id, "admin_kill")` runs whenever a kill was attempted (~621-633). `LocalTarget::kill_process` was hardened by this task to honestly report failure (`survived SIGTERM and SIGKILL`), so an unkillable/permission-mismatched process is permanently hidden from `remote_agent_cleanup` (the sweep only considers `terminated_at IS NULL`) — the exact hazard the code's own comment at admin.rs:534-539 calls "worse than not having the durable store". The sweep's `kill_and_mark` does it correctly (marks only after Ok). No test covers the failed-kill path. Fix: mark only on kill success (leave the record running on failure, as the unreconstructable-backend branch already does).
- [blocker] **F2 (code, `api/admin.rs`): the restart-orphan kill branch kills by the recorded pid without pid-identity verification.** It reconstructs `ProcessHandle{pid: instance.pid}` and kills immediately (~575-600); the sweep deliberately verifies `/proc/<pid>/stat` starttime against `spawned_at` first (`local_pid_matches_record`, with the `remote_agent_cleanup_refuses_recycled_pid` test). After a restart plus pid reuse, an admin kill of a dead agent kills whatever unrelated process now owns the pid. Fix: run the same verification before killing reconstructed local handles.
- [blocker] **F3 (test, `api/spawn.rs`): the spawn-path half of deliverable (6) is unpinned.** The spawn.rs test module has zero `agent_instances` references; `register_spawned_agent_records_backend_owning_handle` asserts only the in-memory registries; every sweep/kill test seeds `AgentInstanceRecord` manually. Deleting the production `record_spawned` call (spawn.rs:2695), the clean-exit mark (spawn.rs:2754), or the orchestrator recording/marking (orchestrator.rs ~500-515, ~581-591) leaves the suite green — the AC "spawn an agent on a real compute target, record its instance" has no regression protection on the recording step.
- [minor] **F4 (code, `vault/mod.rs`): both auth logins omit `X-Vault-Namespace`** while every KV call carries it — with `GYRE_VAULT_NAMESPACE` set, logins hit the root namespace while KV ops target the configured one, breaking both write and agent-resolution paths. The stub doesn't check the header on logins. (Namespace support is beyond the task contract but is half-wired and silently broken.)
- [minor] **F5 (code, `api/oauth.rs`): the enrollment callback fabricates `expires_in = 3600`** when the provider omits it (~370-373) — a hardcoded stand-in for a provider-supplied value, inconsistent with the rotation handler's own honest-expiry policy (which fails the rotation on a missing `expires_in`, with a dedicated test) and this task's no-fabrication rule.
- [minor] **F6 (code, `sqlite/oauth_state.rs`): `provider_config` persists the OAuth `client_secret` in plaintext** in the `oauth_states` table (not the encrypted secrets store); rows live until the hourly cleanup.
- [minor] **F7 (test, `api/admin.rs` / `sqlite/audit.rs`): audit durability/authorization test gaps** — no reopen-same-DB restart-durability test for `/admin/audit` (the pattern exists for every other new store in this task), no direct non-admin-403 test for `/admin/audit` (only for `/admin/server/logs`), and the PG q/zstd path has only SQL-generation assertions. Behavior is correct by construction.
- [minor] **F8 (code, `sqlite/audit.rs`): the q SQL pre-filter's `lower()` is ASCII-only on SQLite**, so non-ASCII case-insensitive matches are false negatives (excluded in SQL before the Unicode-folding Rust re-filter runs); the comment at ~530 overclaims. No false positives; recall edge only.
- [minor] **F9 (docs, `specs/coverage/system/admin-panel.md`): coverage-row evidence cites wrong migration numbers** (000067–000070/000068/000069/000070 vs the shipped 000071_job_runs … 000074_audit_events_tenant_id); the new migrations also skip sequence 000070 (no duplicate — scripts pass — but the "next unused" convention and the citations are inaccurate).

Non-blocking observations (recorded for the verifier / next round): container/kubernetes `kill_process` targets return Ok without post-kill verification (pre-existing targets; the sweep and admin kill inherit unverified kills for those backends — only local kills are verified); `AgentStatus::Failed` instances are never reaped (spec-literal Dead/Stopped/absent, but `fail_agent` leaves running instances that only the same-process exit monitor cleans); gate-agent teardown doesn't mark its instance terminated (sweep re-kills redundantly and mislabels the reason); container/k8s unreapable records lack the 7-day retirement the `other` arm has; `record_cycle` persists empty logs for external-loop jobs; `liveness()` reads only the in-memory ring after a restart; unrecognized `GYRE_SECRET_BACKEND` values silently mean sops; `mem::test_state`'s http client is unbounded (test-only, invariant script still passes).
