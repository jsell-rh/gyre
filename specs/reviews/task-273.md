## Findings (blocking, in verdict.json)

- [F1] **Vault adapter: `id` and `scope_id` are unvalidated KV path segments** — `validate_name` (vault/mod.rs:312-335) guards only names while `index_path` (:347) embeds the raw id (URL-path-sourced in api/secrets.rs delete/rotate) and data/metadata paths embed body-supplied `scope_id`; a `../`-bearing id can read another tenant's `_idx` entry (cross-tenant metadata leak) or aim the metadata DELETE at arbitrary paths in the mount — contradicting the adapter's own documented path-safety boundary. Admin-only endpoints, values stay tenant-scoped, but the boundary claim is false as written. Fix: extend segment validation to `id` and `scope_id`.
- [F2] **Container/kubernetes restart-orphans can be marked terminated without being killed** — maintenance_jobs.rs:274/278 reconstruct `ContainerTarget::new("unused")`/`KubernetesTarget::new("unused")` (no namespace/context/runtime persisted in the instance record); `kubectl delete pod <id>` without `--namespace` misses namespaced pods and the unchanged, pre-existing fail-open `kill_process` (kubernetes.rs:330-334, container.rs, docker.rs: warn + Ok(()) on any non-zero exit) converts the failure into "killed", so `kill_and_mark` records a reap that did not happen. The AC "the process/container is gone" fails for these backends' restart-orphans. Local backend is correct (pid-verified). Fix: persist namespace/context/runtime in AgentInstanceRecord and/or fail the kill on unrecognized non-zero stderr.
- [F3] **NULL-tenant audit events are invisible in the rewritten admin trail** — container_audit.rs emit() (and agent-principal RbacDenied/AbacDenied) carry no workspace_id/user_id, so the adapters store tenant_id NULL and every tenant-scoped /admin/audit query excludes them: an admin kill produces a visible AgentKilled but an invisible container_crashed for the same action; agent denial events are missing from the "trail of all agent and user actions". Fix: scope these emitters via the owning agent's workspace (or the agent's tenant).
- [F4] **OAuth refresh re-serialization drops extra document fields** — secret_rotation.rs:233-240 rebuilds from the typed OAuthCredentialDoc, silently discarding any extra fields an admin supplied; inconsistent with the GCP handler's deliberate Value-preserving fix (commit 3ebd143d). Fix: the same Value-overwrite treatment.
- [F5] **Vault rotate retains old versions** — rotate (vault/mod.rs:800-838) never deletes/destroys prior KV v2 versions, so a rotated (possibly compromised) value stays readable at `?version=N` indefinitely, including under the agent JWT's policy. Fix: destroy/delete prior versions after a successful rotate (or document an operator-set `delete_version_after`).
- [F6] **Jobs tab Schedule column renders fields the API never sends** — TenantSettings.svelte:1840 reads `job.schedule` (and :1841 `job.last_run`) which JobInfo never serializes; the column is dead in production while TenantSettings.test.js:645 mocks those phantom fields, masking it. Fix: render `interval_secs` or drop the column; fix the mock to the real response shape.

## Minor (non-blocking, recorded for completeness)

- spawn.rs:2454-2460 swallows secret-resolution errors and spawns without GYRE_CRED_* env (pre-existing posture for undecryptable DB secrets; the Vault operation itself errors — letter of the fail-closed requirement met, but a fail-open consumer worth a conscious decision).
- docs/server-config.md:81 lists a default for GYRE_CLAUDE_MAX_REDIRECT_URI that the code does not have (it fails closed and rejects that exact relative value); docs/api-reference.md:294 says "302-redirect" where the handler deliberately returns 303. Doc fixes.
- First-write SOPS identity generation is check-then-act (kv_get→generate→kv_set, last-writer-wins): two concurrent first-ever writes can orphan one secret under an overwritten identity. Narrow window; a guarded single-INSERT (or startup provisioning) would close it.
- Unknown GYRE_SECRET_BACKEND values silently default to SOPS (`_ =>` arm in at_rest_format) instead of failing loudly.
- jobs.rs record_run holds the durable-store mutex across retry backoff (latency nit); a run lost after exhausted persist retries is only visible in logs, not on the admin surface; GYRE_JOB_HISTORY_RETENTION_DAYS parse failure silently falls back to 30.
- admin.rs admin_jobs keeps a pre-existing fabricated static fallback list when the registry is empty (test-only path).
- Audit `q` for non-ASCII terms pages through the whole structured-filtered set (perf); OFFSET paging without a snapshot can skip/duplicate under concurrent inserts; `count` in the admin audit response is the page length, not the total.
- Frontend: missing `timestamp_ms` renders epoch-zero instead of '—' (TenantSettings.svelte:1972); Audit tab exposes no `limit` control despite the endpoint supporting it; no test pins the Server Logs level/limit filter wiring or an i18n-key leak guard for the new tabs.
- secret_rotation.rs discards token-endpoint error bodies (failure reasons lack the provider's error code); task-scoped expiring secrets are not scanned by design (documented) — a task secret expiring mid-run gets no refresh/notification.
- Vault `VaultConfig` derives Debug while holding token/secret_id (nothing logs it today); `is_auth_rejected` matches on error-message strings for the login endpoints; `list_by_scope` silently drops entries whose data read returns Ok(None).
- MCP `secrets://names`/`secrets://status` serve the name cascade via the server token under the Vault backend, so an agent can learn names its Vault policy denies (names-only per §7's MCP table; values remain agent-JWT-scoped).
