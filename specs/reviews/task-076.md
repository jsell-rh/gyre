## Acceptance-criteria verification

- **AC1 — `EdgeType::Calls` consistent between passes.** Verified. Both passes emit the same `EdgeType::Calls` variant; task-076 adds provenance only: `resolve_call_edges` (`call_graph_resolve.rs:150-157`) tags Pass 2 edges with `PASS2_EDGE_METADATA` (`gyre-common/src/call_graph.rs:21`), `is_pass2_calls_edge()` (`:25`) is the single reader-side predicate. Both adapters round-trip edge `metadata` (SQLite `sqlite/graph.rs:437,448`; mem `mem_graph.rs:95`), and the content-derived edge id (`calls_edge_id`, SHA-256 over `repo|source|target|calls`) excludes metadata, so re-derivation upserts in place without id churn (task-072 F8 fix preserved).
- **AC2 — `graph_summary` reports completeness.** Verified. `CallGraphMetrics` (`view_query_resolver.rs:111-121`) carries `call_edges_pass1`/`call_edges_pass2`/`call_graph_complete`; the split counts live `Calls` edges by tag. Completeness is **marker-driven, not count-driven**: the pipeline writes a durable `CallGraphRunRecord` (KV namespace `call_graph_status`, key = repo id) only when a Pass 2 run has positive toolchain evidence (`extraction_ran`), and `is_call_graph_complete` (`view_query_resolver.rs:2301`) requires `marker.completed_at ≥ max(last_seen_at)` over live nodes — sound because both adapters unconditionally bump `last_seen_at` on node upsert, so a fresh Pass 1 correctly reads incomplete until Pass 2 re-finishes. A toolchain-less run writes no marker and cannot fabricate completeness. Wired through both `handle_graph_summary` (mcp.rs) and the explorer `execute_tool`; durable in production via the SQLite `kv_store` table.
- **AC3 — `graph_query_dryrun` warns when incomplete.** Verified. `query_uses_calls_edges` (`view_query_resolver.rs:1753`) classifies focus/concept traversal along `calls`, top-level `calls` edge filters, `$callers(`/`$callees(`/`$reachable(...,calls)` expressions, and incoming/outgoing/call-count heat/badge metrics; the warning (spec wording, `:1894`) fires only on `Some(false)` — positive knowledge — so `dry_run()`'s unknown-status delegation never warns spuriously. Both the MCP handler and the explorer tool pass the real marker-derived status.
- **AC4 — Explorer prompt references call graph availability.** Verified. `build_system_prompt` documents `call_graph.call_graph_complete`, the incompleteness warning, and blast-radius/coupling/dead-code guidance; the per-session repository-context block appends a live "Call graph: COMPLETE/INCOMPLETE" line from the durable marker plus the Pass 2 edge count (`explorer_ws.rs:2900-2930`). Test `test_system_prompt_references_call_graph_availability` (`:4081`).
- **AC5 — Pass 2 duration logged as a metric.** Verified. `gyre_graph_pass2_duration_seconds` Prometheus histogram (label `language`, buckets 0.5s–120s spanning the §9 targets) + `observe_pass2_duration` (`metrics.rs:23,68-76,128`); the step-7 spawn times the whole run and `record_pass2_telemetry` (`graph_extraction.rs:1018`) observes per-language durations, logs the total with the spec targets inline, and persists the marker. Wired at all four production call sites — grep confirms no unwired caller.
- **AC6 — Unit tests for updated MCP tool responses.** Verified. `mcp_graph_summary_call_graph_metrics_tool_call` (mcp.rs:5320) and `mcp_graph_query_dryrun_call_graph_warning_tool_call` (:5437) drive the real JSON-RPC dispatch path against the real KV store and assert both directions of each transition (incomplete→complete, warn→silent), killing never-warn/always-warn/always-complete stubs.
