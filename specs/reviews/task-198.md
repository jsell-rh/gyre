- **Persistence is real, not a stand-in.** The `spec_links` table has all 13 specced columns with the specced nullability (`source_sha TEXT NOT NULL`, `target_sha TEXT NOT NULL`, `status TEXT NOT NULL DEFAULT 'active'`), registered in `schema.rs`, created by migration `000059` (next unused Diesel version after the base's `000056_spec_assertion_results` — `check-migration-versions.sh` passes). The `Option`↔NOT-NULL mapping (`None` ↔ `''` for `source_repo_id`/`target_sha`) is documented in both SQL adapters, exactly as the task plan sanctions.
- **`source_sha` is the real blob SHA.** `sync_spec_ledger` records each manifest spec's `get_blob_sha` (git at HEAD) into `manifest_sha_by_path` and uses it for the link's `source_sha` — the same value the spec's own ledger entry gets. No hardcoding; the `unwrap_or_default` arm is unreachable (the map is populated for every entry in the same loop).
- **All writes go through the repository** (SQL table authoritative, cache write-through): `sync_spec_ledger` issues one `replace_for_source` per manifest spec — including empty link sets, so manifest-removed links are deleted from the table rather than resurrected at boot; staleness transitions and cross-workspace re-resolution (`spec_link_staleness.rs`) call `save`; repo deletion (`api/repos.rs::delete_repo`) calls `delete_by_source_repo`. Every `spec_links_store` mutation site in production code has a matching durable write; `spec_patrol`, `merge_processor`, `api/graph`, `api/specs` readers are unchanged read-only consumers.
- **Boot rebuild is real.** `load_spec_links_into_store` (called from `build_state` and the mem test constructor) blocks on `list_all` and replaces the cache; read failure is logged at error level rather than masquerading as an empty graph. The `SpecLinksStore` alias now carries the sanctioned `in-memory-state-stores:ok` marker with the frozen exemption count lowered 5→4 — the exact remediation mechanism `check-in-memory-state-stores.sh` itself prescribes for a fixed site (script passes).
- **Cross-repo scoping is sound.** The id is repo-scoped (`spec_link_id`), and both the in-memory retain and the SQL adapters use the same `(source_repo_id, source_path)` key, so two repos carrying the same spec path cannot clobber each other's rows — a genuine improvement over the old tenant-wide-path retain, covered by a dedicated regression test.
