- **Aggregation (Part 2)**: `list_for_user` (SQLite/Postgres parity, mem now real) unions `spec_approvals` (LEFT JOIN `spec_ledger_entries` on `spec_path` — `?workspace_id=` is a real SQL filter that drops NULL-workspace rows, replacing the old stamping) with `audit_events` rows of the three judgment event types attributed via `user_id`, sorts the merged stream reverse-chronologically with a deterministic `entity_ref` tie-break, and applies limit/offset only after the union+sort. Adapter tests prove each property and that foreign users' entries never leak.
- **Write paths (Part 3)**: trust transition writes `trust_change` (from/to/workspace_id, acting user, only on real transition, failure propagates); human approval on an MR with failed gate results writes one `gate_override` per FAILED gate (mr_id/gate_id/gate_type/from/to; agent-token approvals excluded because `auth.user_id` is None); meta-spec registry create/update write `meta_spec_publish` with kind/name/version/content_hash and workspace attribution from scope. - **Inbox filtering**: `exclude_types` added to `NotificationRepository::list_for_user`/`count_unresolved`, applied in SQL (`NOT IN` before limit/offset) in SQLite+Postgres, in-memory in mem; `users.rs` inbox + badge endpoints and the MCP `notifications://` tool load disabled types from `user_notification_preferences` (no row = enabled); PUT rejects unknown canonical names with 400 via `NotificationType::parse`; background de-dup callers pass `&[]` (all call sites updated — graph_extraction, merge_processor, spec_patrol, etc., proven by compilation + tests).
- **Auth provider info**: migration 000056 adds `users.oidc_issuer`/`last_login_at`; `validate_jwt` records both via `UserRepository::record_login` — a single-statement conditional UPDATE (debounce evaluated in the WHERE clause, no read-modify-write race), identical semantics in SQLite/Postgres/mem; `GET /users/me` returns both read-only; `PUT /users/me` has no field for either and `update()` preserves them (adapter test). Web Profile tab renders both, and the badge now uses the server-side count endpoint rather than a client-side page count.
