## Findings

- [+] **F1 (minor, but against the candidate's own amended contract): `ComputeTargetUnavailable` has no profile toggle — 39 of 40 `NotificationType` variants are togglable.** `gyre-common/src/notification.rs` declares 40 variants; `web/src/components/UserProfile.svelte` `NOTIF_TYPE_IDS` lists 39 — `ComputeTargetUnavailable` (notification.rs:124, Priority-1 inbox type emitted to workspace admins by `signal_chain.rs:1395` and `ralph_loop.rs:408`, sitting between `MergeQueueEscalation` and `ImpersonationRequest` in declaration order) is missing, and has no `user_profile.notif_types.*` label in `web/src/locales/en.json`. Probe (enum extracted from Rust vs ids extracted from the Svelte list): `in rust not svelte: ['ComputeTargetUnavailable']`. The amended HSI §12 (written by this very candidate) says "Per-notification-type toggles (enable/disable **any** `NotificationType` variant)", and the test's own comment cites review F3 as requiring exactly that — so a human still cannot disable this one type from the profile UI. Compounding it, `web/src/__tests__/UserProfile.test.js:228` hardcodes `expect(checkboxes.length).toBe(39)` — a mirrored-logic assertion that matches the implementation rather than the enum and would not catch this omission or a future 41st variant.
  **Repair path (mechanical):** add `'ComputeTargetUnavailable'` to `NOTIF_TYPE_IDS` (after `'MergeQueueEscalation'`), add the `user_profile.notif_types.ComputeTargetUnavailable` label to `en.json` (and other locales if they carry the full set), and change the test to assert 40 (ideally derived from a shared canonical list rather than a literal). Backend needs no change — `PUT /users/me/notification-preferences` already accepts the canonical name.
