## Verified against each acceptance criterion

1. **Spec amendment (Part 1)** — HSI §12 now documents the four concrete sources in a table (category / table / human-attribution key / workspace-attribution key), fixes `?type=` to the exact `JudgmentType` wire strings (`approval|rejection|gate|trust|meta-spec`), specifies the inbox/badge/MCP-tool filter contract with the background-job exemption, and defines auth-provider recording semantics. `agent-gates.md` §Spec Approval Ledger is amended coherently for the Approved→Rejected decline-after-approval path that rejection attribution requires.
2. **`JudgmentType::GateOverride`** — added with `as_str() = "gate"`, `from_db_str("gate")` parses; enum made `Copy`; wire strings unchanged for existing variants.
3. **Aggregation (Part 2)** — sqlite `list_for_user` now: (a) filters `?workspace_id=` in SQL (LEFT JOIN `spec_ledger_entries` on `spec_path`; NULL-workspace entries excluded when the filter is set — no longer stamps the param); (b) unions `audit_events` rows (`event_type IN ('gate_override','trust_change','meta_spec_publish')`, `user_id = approver`) read through the shared `AuditEventRow` materialization so compressed `detail_zstd` payloads decompress (dedicated test); (c) sorts reverse-chron with deterministic tie-break and applies limit/offset after the merge; (d) attributes rejections/withdrawals to the declining human (`rejected_by`/`revoked_by`), not the original approver (dedicated test with a negative assertion on the approver's ledger). Postgres adapter mirrors the implementation line-for-line with a shared `JUDGMENT_AUDIT_TYPES` parity constant; mem adapter implements the same semantics over the *shared* stores (`MemJudgmentLedgerRepository::with_sources` in `lib.rs` wires the same `Arc` stores the write paths use — not a parallel fake).
4. **Trust-change write path** — `PUT /workspaces/:id` writes a `trust_change` `AuditEvent` (from/to/workspace_id, `user_id` = acting human) only on a real transition, failure-propagating (`?`). Test asserts the event, attribution, and that a no-change PUT writes nothing.
5. **Gate-override write path** — human (`auth.user_id.is_some()`) `Approved` review on an MR with failed gate results writes one `gate_override` event per failed gate (mr_id, gate_id, gate_type, failed→overridden). Test includes a negative control (agent-token approval writes nothing) and the end-to-end `?type=gate` ledger read.
6. **Meta-spec publish write path** — registry create/update write `meta_spec_publish` events (kind/name/version/content_hash, workspace attribution from `scope`/`scope_id`; Global/Tenant scopes deliberately unattributed so the workspace filter excludes them rather than mis-filing them). Test asserts both create and update.
7. **Inbox filtering** — `NotificationRepository::list_for_user`/`count_unresolved` take `exclude_types`, applied in-query before limit/offset (sqlite/postgres/mem parity); inbox + badge + MCP `notifications://` tool load disabled types from `user_notification_prefs`; PUT normalizes legacy parse aliases to canonical `as_str()` names and 400s unknown types (an alias would otherwise be a silently inert toggle — dedicated test).
