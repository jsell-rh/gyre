## Findings

- [open] **F1 (major, code): a corrupt workspace meta-spec set anywhere breaks every Global/Workspace meta-spec approval — 500 returned after the approval was already persisted.** In `update_meta_spec_registry` (`crates/gyre-server/src/api/meta_specs.rs`), the Global/Workspace branch of the `newly_approved` fan-out (~line 1749) resolves each workspace's effective set with `resolve_effective_meta_spec_set(&state, ws).await?`. `state.meta_specs.update(&ms)` has already persisted the approval at that point, so when ANY workspace's stored `meta_spec_sets` JSON is unreadable (corrupt row / deserialization error), the handler returns 500 while (a) the approval IS applied (`approval_status: Approved` persisted), and (b) the fan-out is partially executed — workspaces listed before the corrupt one already received reconciliation tasks. Reproduced at candidate HEAD with a temporary probe test (`review_probe_corrupt_set_breaks_global_approval`): approval status **500**, persisted status **Approved** (evidence: `probe-corrupt-set-global-approval.txt`; probe removed, tree restored to candidate HEAD). This is a regression from base `a884329d7`, which treated unreadable sets as non-binding (`.ok()` chains) so the approval succeeded; and it is inconsistent with the identical failure class one branch above in the same function: `run_tenant_reconciliation` fails closed by skipping the workspace (`workspaces_skipped_error` + warn log). Remedy: match on the resolve result in the Global/Workspace fan-out and skip that workspace with a warn log (same fail-closed-skip as the tenant controller); add a killing test (corrupt unrelated workspace set + Global approval → 200, corrupt workspace skipped, no tasks for it).
- [open] **F2 (minor, code): new compiler warning.** `tenant_meta_spec_set_requires_admin` (~`meta_specs.rs:990`) leaves the `tokio::task::block_in_place(...)` `Result` unused (`unused_must_use`); the warning prints on every gyre-server test build. Fix: `let _ = ...`.
