## Verified against the acceptance criteria

- **Six Groups endpoints per RFC 7644 through the production router.** Routes registered in `api/mod.rs` (`/scim/v2/Groups` GET+POST, `/scim/v2/Groups/:id` GET+PUT+PATCH+DELETE); handlers in `api/scim.rs` implement the RFC 7643 §4.2 Group schema (schemas/id/externalId/displayName/members value+display/meta), 1-based `startIndex`/`count` pagination with unpaginated `totalResults`, `displayName eq`/`externalId eq` filters, 404 on unknown id for GET/PUT/PATCH/DELETE, POST idempotent on externalId (re-push → 200 stored resource), PUT replaces the membership set exactly (externalId immutable join key), PATCH add/remove/replace members including the `members[value eq "x"]` path-filter and bare-body forms plus `replace displayName`, DELETE removes every member (running the revocation effect per member) then group + membership rows. Every handler calls the fail-closed `check_scim_auth` first (403 on unset `GYRE_SCIM_TOKEN`, missing header, wrong bearer; constant-time compare); the `/scim/v2/` prefix exemption in `require_auth_middleware`/`last_seen_middleware` (task-265) covers the new routes. `/scim/v2/Groups*` are ABAC-exempt with per-handler auth — `check-abac-exempt-handlers.sh` passes.
- **Mapping surface.** `PUT/GET /api/v1/workspaces/:id/scim-mappings` (`api/scim_mappings.rs`): whole-set PUT validated before persist (unknown role / empty / duplicate `idp_group` → 400, never partially applied), tenant containment via `load_workspace`, authorized by the ABAC `RouteResourceMapping` (`scim_mapping` resource, `builtin:scim-mapping-management`, priority 808, workspace Owner/Admin) **plus** a per-handler `can_manage` guard mirroring `can_manage_membership` — a plain Developer member gets 403 and the escalation attempt persists nothing (test-asserted). The test comment is candid that the 403 comes from the handler guard (global Developer write access passes ABAC) — defense in depth is present and the task's "workspace-admin authorized, registered in the ABAC RouteResourceMapping" is satisfied on both layers.
- **Mapping effects, both halves.** `apply_member_added`/`apply_member_removed` run from every membership-changing push (create with members, PUT, PATCH, DELETE). Adding U to a group whose externalId (else displayName) matches a workspace mapping creates U's `WorkspaceMembership` with the mapped role — accepted on creation, tenant-contained (cross-tenant users skipped, never fabricated), idempotent (existing membership never duplicated or rewritten). Removing U revokes the mapped membership only when it holds the mapped role (an admin-granted different-role grant is left intact — correct conservatism). Unmapped groups create nothing anywhere. Each effect emits an audit event (`workspace_membership_created`/`revoked`, `source: "scim"`).
- **Durable storage behind ports, both adapters, next migration sequence.** `gyre-ports` `ScimGroupRepository`/`ScimMappingRepository`; SQLite and PostgreSQL adapters (diesel, `spawn_blocking`, transactions for delete/replace) over migration `2026-11-14-000068_scim_groups_and_mappings` — plain portable SQL (partial unique index on `external_id` runs on both backends; `check-migration-sql-portability` passes; `000068` is the next unused number). Wired through `build_state`'s `store!` pattern — no in-memory AppState store (`check-in-memory-state-stores` passes). The mem adapter guards the duplicate-external_id port contract in code (`check-mem-port-contracts` passes); the SQLite unique-violation matcher handles both SQLite's column-form and PG's index-name-form messages, and the adapter contract test proves it fires.
- **Test quality (no inflation found).** `tests/scim_groups.rs` (6 tests) drives every request through the full production `build_router()` stack over a real SQLite temp-file database: the CRUD/pagination/filter/404 surface; SCIM-token enforcement on each endpoint including unset-token fail-closed and global-token-is-not-SCIM; the verification-intent scenario end-to-end (map G→Developer in W, push U in — membership row created and U's authenticated `GET /workspaces/{W}/members` returns 200; remove U via PATCH path-filter — membership gone and the same access 403s; PUT re-add and PUT-empty-set revoke; owner untouched); idempotent re-push; Developer-member 403 on mapping PUT with non-application asserted; the unmapped control case (no `WorkspaceMembership` row anywhere for U, access denied); restart survival (full state rebuild over the same db file — mapping, group id, and the effect all survive); displayName-keyed mapping and cross-tenant containment.
