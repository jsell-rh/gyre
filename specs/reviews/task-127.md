### Findings

- [x] **F1 (code, user-visible): two i18n keys referenced by `TenantSettings.svelte` are missing from `web/src/locales/en.json` — the Tenant User Management page renders raw key strings.** `web/src/components/TenantSettings.svelte` line 813 (`$t('tenant_settings.users.col_role')`, users table header), line 855 (`$t('tenant_settings.users.count_note', …)`, count note under the table), and line 1608 (info-card label) reference keys that do not exist in any locale (`tenant_settings.users` in en.json has `col_user`/`col_status`/`col_created` but no `col_role`, and no `count_note`; only `workspace_settings.teams.col_role` exists). svelte-i18n with no missing-key handler returns the key itself, so every TenantAdmin viewing the Users tab sees the literal strings `tenant_settings.users.col_role` (table header) and `tenant_settings.users.count_note` (note line) whenever the list is non-empty. Reproduced dynamically: a temporary vitest render of TenantSettings with one user (real i18n setup, no mock) printed `HEADER: "Usertenant_settings.users.col_roleStatusCreatedActions"` and `NOTE: "tenant_settings.users.count_note"` (probe source, command, and output in `/tmp/stage/review-evidence/i18n-missing-keys.md`; the probe test file was deleted after capture). The existing TenantSettings tests pass because they never assert those cells' text. **Repair:** add `"col_role": "Role"` and `"count_note": "Showing {shown} of {total} users"` (or equivalent) to `tenant_settings.users` in `web/src/locales/en.json`, plus a guard asserting the rendered table header/note contain no raw `tenant_settings.users.` key strings (the deleted probe is a ready-made template), and record the repair commit in task-127.md `commits:`.
