## Verified against the acceptance criteria

- **AC1 — every commit surface signs.** All four surfaces route through the new shared entry point `commit_signatures::sign_commit`: `jj new` (api/jj.rs; `JjOpsPort::jj_new` now returns `JjNewChange {change_id, commit_id}` so the content-addressed commit id is signable — real jj template `change_id ++ "\x1f" ++ commit_id`, adapter-tested), `jj squash` (api/jj.rs), git HTTP push (git_http.rs `git_receive_pack`: signs every landed commit *before* responding; failure undoes refs, emits `git_push_rejected` audit naming the `commit-signing` gate, rejects 403/502), and MR merge commits (merge_processor.rs `sign_merge_commit`, wired into both `process_next` — failure triggers the existing post-merge recovery protocol — and the atomic-group path — failure rolls the group back). `none` mode stays an explicit opt-in and is never the default. Tests: `jj_new_signs_commit_with_persisted_validated_signature`, `push_signs_every_landed_commit`, `merge_commit_signing_persists_attribution_bound_record` (each also drives the real verification path).
- **AC2 — keyless by default.** `SigningMode::parse`: unset/empty → `Fulcio`; `local`/`none` explicit; any other value is a hard startup error (no silent `_ => Local` downgrade). `build_state` uses `SigningConfig::from_env`. Test fixtures that need a reachable stack explicitly configure `local` (mem fixture) or set `GYRE_SIGNING_MODE=local` (integration harnesses) — documented operator opt-in, not a default change. Unit test `signing_mode_default_and_explicit_values` kills the old default.
- **AC3 — no silent degradation.** `sign_commit` returns `CommitSigningError` (`NoOidcIdentity` → 403, `SigningStackFailed` → 502 naming the mode); `sigstore::jwt_is_presentable` gates *before* any HTTP call so a dev-token/empty bearer is never presented to Fulcio. The only fallback is `GYRE_SIGNING_FULCIO_FALLBACK=local`, warn-logged, with the stored record honestly carrying `sigstore_mode=local`. Tests assert both the error status naming the mode *and* that no local-key record exists for the operation (`jj_squash_fulcio_unreachable_fails_loudly_no_local_fallback`, `jj_squash_fulcio_without_jwt_is_refused`, `push_rejected_loudly_when_fulcio_unreachable` — also asserts refs undone and the audited rejection, `merge_commit_signing_fails_loudly_when_fulcio_unreachable`).
- **AC4 — attribution cryptographically bound.** `signed_commit_payload` builds the canonical JSON `{commit_sha, task_id, spawned_by}`; the local Ed25519 signature (`sign_commit_local`), the keyless ECDSA signature (`sign_commit_keyless` step 4), and the Rekor hashedrekord digest (`commit_digest`) all cover it; verification (`verify_commit_signature`, `check_signature`, `check_rekor_entry`) recomputes the payload from the record's OWN fields, so tampering `task_id`/`spawned_by` breaks both the signature check and the Rekor content match. Tests implement the task's second verification probe verbatim: `local_verify_fails_on_tampered_task_attribution` and `sigstore::tests::verification_fails_on_tampered_task_attribution` (asserts `!signature_valid && !rekor_entry_exists` while certificate/subject stay valid).
- **AC5 — real Rekor for attestation bundles.** `NoopRekorClient` is deleted from the codebase (only a historical mention in a doc comment); `HttpRekorClient` (latency-bounded reqwest, 10 s) is wired in `build_state` and the mem fixture. It submits each signed bundle as a hashedrekord whose digest covers `unsigned_canonical_json()` — the exact bytes the forge's `bundle_signature` signs — with the forge public key PEM in `publicKey.content`; the returned entry UUID is persisted (KV `rekor_attestation_entries`, keyed by MR id). Unconfigured log, unsigned bundle, and HTTP failure are explicit `Err`s; `store_merge_attestation_bundle` returns `Ok(())` only when storage AND submission succeeded, and treats a stray `Ok(None)` as an error — never silent success. Wire behavior proven by the real-server adapter tests above; storage-path handling proven by `merge_attestation::rekor_storage_tests` (UUID persisted; outage → explicit error, no UUID recorded, bundle still stored).
