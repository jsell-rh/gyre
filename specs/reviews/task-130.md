Findings:

- **F1 (blocking, code): candidate-caused regression in `m18_oidc_integration` — spawn against a repo whose `workspace_id` has no workspace row now downgrades the agent to a legacy UUID token, breaking 3 pre-existing tests and the `cargo test --all` acceptance criterion.** `spawn_agent_core`'s new mint gate (spawn.rs:437-470) resolves the tenant via `state.workspaces.find_by_id(&repo.workspace_id)`; when the row is absent it skips the JWT mint entirely and falls back to a UUID token. That state is reachable through the public API: `POST /api/v1/repos` accepts any `workspace_id` with no existence check or auto-create (repos.rs:135-176 stores it verbatim), and the m18 fixtures create repos with unseeded workspace ids (`ws-m18`, `ws-jwt-auth`, `ws-info`) without ever creating workspace rows. Result at the candidate: `spawn_returns_jwt_token`, `jwt_token_authenticates_api_calls`, `token_info_for_jwt_agent_token` fail deterministically (`spawn token must be a JWT (starts with 'ey'), got: 5c97733f-…`). At the base `ed57c723` the same binary passes **8/8** (isolated worktree run, `/tmp/stage/review-evidence/test-m18-at-base.log`), so this is a regression introduced by this task, not a pre-existing failure. Discriminating probe: the same spawn flow **with** a workspace row created first mints a proper JWT (`/tmp/stage/review-evidence/probe-m18-workspace.log`), proving the fallback path is the workspace-unresolvable one. Beyond the test failures, the production behavior change is itself questionable: an operator who creates a repo via the REST API (no workspace validation) and spawns a worker gets a silently unscoped legacy UUID token where the base minted a JWT. The fail-closed intent (task-097 F3: never fabricate a tenant) is right, but the reachable dangling-workspace state was not accounted for, and the shipped note's test evidence stopped at `--lib` (whose fixtures always seed workspaces), missing the integration suite in the same crate. Reproduce: `SKIP_WEB_BUILD=1 cargo test -p gyre-server --test m18_oidc_integration` (candidate: 3 failed; base: 8 passed). Remedy: make the dangling state unreachable or the tests honest — validate workspace existence in `create_repo` (400/404 on unknown `workspace_id`) and update the m18 fixtures to create their workspaces, or at minimum update the m18 fixtures and document the UUID-downgrade semantics for dangling workspace refs; either way `cargo test -p gyre-server` (lib + all integration binaries) must pass at the candidate.
