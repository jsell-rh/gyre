## Findings

### F1 (blocking — missing enforcement): the invalidation write silently no-ops when the ledger lookup fails or the spec has no ledger entry

`crates/gyre-server/src/api/meta_specs.rs:9193` — the ledger update that implements the task's central requirement is guarded by `if let Ok(Some(mut entry)) = state.spec_ledger.find_by_path(&spec_path).await`:

- **Err case:** on a spec-ledger storage error the new binding set has ALREADY been persisted (lines 9147–9177) and the stale-pin dedup keys cleared, but `bindings_sha`/`approval_status` are left untouched and the handler returns **200 OK** with no log. The prior approval stays valid while prompt-assembly band 3 injects the new pinned prompts — agents run under an approval that no longer covers the injected meta-spec content, i.e. exactly the cascade failure this task closes. The same handler propagates errors from the identical lookup at its top (`map_err(ApiError::Internal)?`, line 9057) and from `spec_ledger.save` (line 9200) — only this read is swallowed.
- **Ok(None) case:** reachable for a global Admin (the workspace gate only constrains non-admins); the binding rows persist with no ledger entry, so the set is never covered by any registry SHA. When the spec is later registered, `sync_spec_ledger` creates the entry with `bindings_sha: ""` (spec_registry.rs:578), and an approval granted after registration covers the content-only identity while band 3 injects the bound prompts — bindings that permanently escape the "stored in the spec registry alongside other spec metadata" contract (agent-runtime.md §2).

Fix: fail the PUT (500) when the ledger lookup errors, and reject bindings for a spec absent from the ledger (404/400) so no binding can exist outside registry-SHA coverage. Related, lower-severity instances of the same fail-open read pattern (degrade to the weaker pre-existing check on lookup error, rather than skipping a write): `api/spawn.rs:767`, `api/gates.rs:832`/`:892` — the Ok(None) case there is a documented scope decision; only the Err swallowing is exposure.
