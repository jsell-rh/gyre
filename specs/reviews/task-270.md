## Verified

**Agent-principal default-branch push protection** (git_http.rs:730-815): direct, unconditional check in `git_receive_pack` — not an opt-in pre-accept gate — placed after repo resolution/authorization and BEFORE `run_git_stateless("receive-pack")`, so a rejected push never updates the ref (pinned by `git rev-parse` assertions in the tests). Caller class `auth.user_id.is_none() && !auth.is_system_principal()` verified against every auth.rs token path: agent uuid/JWT tokens construct `AuthenticatedAgent` with `user_id: None` (auth.rs:1515, auth.rs:1823); human API-key/Keycloak-JWT paths resolve `user_id: Some`; the system principal is discriminated by the unforgeable `agent_id == "system" && user_id.is_none()` (auth.rs:1161). Default branch comes from the Repository record (`resolved.default_branch`), never a literal "main" — `protection_resolves_real_default_branch_not_literal_main` sets `default_branch = "trunk"` and proves refs/heads/trunk is rejected while refs/heads/main is accepted there. The 403 body directs the agent to the MR flow (`gyre_agent_complete`).

**Prior finding 1 (deletion bypass) — fixed**: the guard matches `parse_ref_update_commands` (raw pkt-line commands, deletions included, git_http.rs:1842); `parse_ref_updates` is now a deletion-filtering wrapper with unchanged semantics (pinned by `parse_ref_updates_deletion_skipped`). `agent_deletion_of_default_branch_rejected` seeds refs/heads/main via `update-ref`, sends a delete-command receive-pack body with an agent token, and asserts 403 with the ref surviving — it fails on the pre-repair guard.

**Prior finding 2 (agent-reviewer nudge dedup) — fixed**: KV backoff `pr_hygiene_nudge_backoff` keyed `{mr_id}:{agent_id}`, window = nudge threshold (pr_hygiene.rs:395-440). `consecutive_evaluations_do_not_duplicate_agent_reviewer_nudges` counts message-bus `review_nudge` emissions across two evaluations (asserts exactly 1) and asserts the backoff is persisted in KV (restart safety).

**PR hygiene job**: `pr_hygiene_check` registered in jobs.rs on an interval (default 300s, `run_at_utc_hour: None` — pinned by `pr_hygiene_check_registered_on_interval_not_daily`, which also triggers the registered handler and asserts a real successful run) and spawned via `jobs::spawn_job` in main.rs. Stale classes use real persisted state: `MergeRequest.updated_at`, reviewers, `has_conflicts` plus a real libgit2 in-memory merge-base conflict check (`git2_ops.rs` `can_merge` — no working-tree modification), and review records. All four actions are real and recorded: reviewer nudge (ReviewerNudge notification deduped via `has_active_notification`; no-reviewer MRs escalate MrUnreviewed to Developers/Admins), conflicted MRs get a jj rebase through the existing machinery for Active agent authors with live worktrees (shared 60s `jj_rebase_backoff` window; call args asserted via the ConfigurableJjOps double: worktree, "@", target branch) or a MrNeedsRebase escalation otherwise — never silence; long-open MRs escalate MrStaleEscalation at priority 3 to Admins/Owners; abandoned MRs close with a persisted status transition, an explanatory MR comment (author "system"), author delivery (agent bus message with the explanation / user notification), and pr_hygiene audit events. Thresholds are env-configurable with sane non-zero defaults (2d/7d/30d; `from_env` filters zero). The daily `abandoned_branch_check` job is untouched.

**Human/system push path preserved**: `human_push_to_default_branch_accepted_and_spec_lifecycle_runs` seeds a real user + API key + Developer workspace membership, pushes a specs/ change to refs/heads/main, and asserts 200, the ref on disk, and a `spec_changed` audit event with an auto-created task_id — spec-lifecycle.md §Automatic Task Creation stays live. Existing git_http tests pushing to main with the global (system) test token are unchanged and stay exempt.

**Server-side landing unaffected**: the merge queue lands via the git_ops port, never the HTTP handler; `merge_queue_auto_merges_mr_and_commit_on_main` (git_integration.rs) was updated to establish main with the system token while the agent pushes its feature branch, so merge-queue landing on main is still exercised end-to-end.

**Test quality**: push tests use real bare git repos, real commits built with git plumbing, real HTTP through the axum router with real token auth, and verify ref state on disk — each fails if the guard is removed. Hygiene tests use real mem-adapter state (notifications, reviews, MRs, KV) with git/jj doubles only at the port boundary, matching the established merge-processor test pattern.
