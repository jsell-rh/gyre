## Findings (blocking)

1. **Agent-principal default-branch DELETION bypasses the protection** — `crates/gyre-server/src/git_http.rs`. The guard tests `ref_updates.iter().any(|u| u.refname == default_ref)` (git_http.rs:756), but `parse_ref_updates` deliberately drops deletions from that list ("Only record pushes of real commits (not deletions)", git_http.rs:1637-1646: `if new != zeros { updates.push(...) }`). A ref deletion is a push whose target ref is the default branch (`git push origin :main` → command line `<old-sha> <40×0> refs/heads/main`), and `git receive-pack --stateless-rpc` applies deletions — no `receive.denyDeletes` is configured anywhere in the tree (only `receive.denyCurrentBranch=ignore` for the git2 clones; the HTTP-served repos are bare, where deleting even HEAD's target branch is allowed with a warning). Reproduction for the verifier: with an agent token, POST `/git/{ws}/{repo}/git-receive-pack` a body of `pkt-line("<old> 0000000000000000000000000000000000000000 refs/heads/{default_branch}\n")` + `0000` — the 403 never fires, git deletes the default-branch ref. The task contract requires rejecting "pushes whose target ref is the repo's default branch" for agent principals; this is the most destructive form of that push class. Fix: match the default ref on the raw parsed commands before the deletion filter (or include deletions of the default branch in the rejected set), with a test pinning it.
2. **Agent-reviewer nudges are not deduplicated across evaluations** — `crates/gyre-server/src/pr_hygiene.rs:593-684` (`nudge_unreviewed`). A *user* reviewer is deduped through `has_active_notification` before the notification row is created, but an *agent* reviewer (explicitly supported: the reviewer id is resolved against `state.agents`) gets `emit_event(Custom("review_nudge"))` unconditionally — no notification row, no KV backoff, unlike the rebase path. On the 5-minute cadence, an MR with an agent reviewer and zero reviews older than the nudge threshold receives a duplicate `review_nudge` message every evaluation until reviewed or escalated — violating the "each idempotent (no duplicate notifications for the same stale MR on consecutive runs)" acceptance criterion for this delivery path. The shipped idempotence test covers only the user path. Fix: dedupe agent nudges the same way (e.g., a per-(agent, MR) KV backoff like `jj_rebase_backoff`, or an inbox-backed record) + a consecutive-run test with an agent reviewer.
