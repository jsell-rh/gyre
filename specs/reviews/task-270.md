## Verified working (per acceptance criterion)

- **Agent-principal push protection.** `git_receive_pack` (git_http.rs) rejects with 403 + an explicit MR-flow-directing reason any push whose target ref is `refs/heads/{default_branch}` when the caller is an agent principal (`auth.user_id.is_none() && !auth.is_system_principal()`). The check is a direct, unconditional check in the handler (not an opt-in named gate), placed after repo-access/ABAC authorization and **before** `git receive-pack` executes — the ref is never updated server-side on rejection (tests assert `ref_exists` false). The target ref is matched against the RAW pkt-line commands (`parse_ref_update_commands`), so agent-principal **deletion** of the default branch is rejected too (a delete-only body applies without a packfile — confirmed by probe). Rejection emits a `PushRejected` bus event and a `GitPushRejected` audit event (gate `default-branch-protection`, outcome Blocked) naming the caller. Tests: `agent_push_to_default_branch_rejected_directing_to_mr_flow` (403 + body names "merge request" + ref absent + audit), `agent_push_to_feature_branch_succeeds` (same token, feature branch, ref lands).
- **Human push path preserved.** `human_push_to_default_branch_accepted_and_spec_lifecycle_runs` authenticates a real API key resolving to a Developer user (user_id Some → not an agent principal), pushes a nested `specs/system/human-push-spec.md` commit to `refs/heads/main` with a real packfile, asserts 200 + ref landed + a `spec_changed` audit event whose `task_id` is set (spec-lifecycle task creation). The global dev token resolves as the system principal (`is_system_principal()`), so every pre-existing `Bearer test-token` main-branch push test is unaffected — confirmed in `auth.rs` (global-token link returns `agent_id: "system"`, `user_id: None`).
- **Real default branch per repo.** `default_branch` comes from the `Repository` record (`Repository::new` defaults to "main"; no hardcoded literal at the check site). `protection_resolves_real_default_branch_not_literal_main` flips the repo to `trunk`, asserts an agent push to a branch literally named `main` is accepted and `refs/heads/trunk` is rejected.
- **Server-side landing unaffected.** The rejection lives only in the HTTP handler; merge-queue landing goes through the git_ops port. The existing `merge_queue_auto_merges_mr_and_commit_on_main` integration test covers it — its only change is seeding `main` with the system token (the agent pushes its feature branch), with the landing assertions intact.
- **Unreviewed nudge / no-reviewers escalation / fresh no-op.** `pr_hygiene.rs` `nudge_unreviewed`: zero review records (real `reviews.list_reviews`) past the nudge threshold → `ReviewerNudge` notification per assigned reviewer; empty `reviewers` → `MrUnreviewed` escalation to workspace Developers/Admins (test asserts Viewer excluded); fresh MR under threshold → no action and stays Open. `reviewed_mr_is_not_unreviewed` guards the review-record check.
- **Abandoned close.** `close_abandoned` persists the status transition (domain `transition_status` Open/Approved → Closed, verified valid by gyre-domain tests), mirrors the close endpoint's trace deletion, records an explanatory MR comment (`reviews.add_comment`), emits `MrStatusChanged`, delivers the explanation to the author (agent author → bus message `mr_auto_closed`; user author → `MrAutoClosed` notification), notifies Admins/Owners, and writes a `pr_hygiene` audit event. Test asserts every one of these (status, exactly one comment containing "closed automatically", author message payload, admin notification row, audit `close_abandoned`).
- **Conflicted action.** `is_conflicted` = persisted `has_conflicts` or a real merge-base check (`GitOpsPort::can_merge`; infra errors are NOT treated as conflicts — correct fail-closed-on-noise choice). `act_on_conflict`: agent-authored branch with a live worktree (same safeguards as `merge_processor::find_rebase_targets`, shared 60s KV backoff namespace) → real `jj_ops.jj_rebase` in the author's worktree, audited as `jj_rebase` (source `pr_hygiene`), conflict flag repaired on success; otherwise (or on rebase conflict) → `MrNeedsRebase` escalation to Developers/Admins + `rebase_required` audit. Tests drive both paths with the `ConfigurableGitOps`/`ConfigurableJjOps` doubles (jj call recorded; escalation row count 1 when no agent; no escalation after a successful rebase).
- **Continuous cadence + idempotence.** Registered in `jobs.rs` as `pr_hygiene_check` with `interval_secs` (default 300, `GYRE_PR_HYGIENE_INTERVAL_SECS`) and `run_at_utc_hour: None`; executed by `spawn_job` in `main.rs` after `start_job_registry`. `pr_hygiene_check_registered_on_interval_not_daily` asserts the registration shape and that a manual trigger runs a real evaluation (history status success). User-facing actions dedupe through `has_active_notification` (exact (ws, user, type, entity) active-notification lookup — implemented in mem, SQLite, and PostgreSQL adapters); agent-reviewer bus nudges dedupe through a persisted KV backoff keyed (MR, agent). `consecutive_evaluations_do_not_duplicate_notifications` and `…_agent_reviewer_nudges` run two evaluations and assert exactly one delivery each (agent path also asserts the KV backoff row exists).
