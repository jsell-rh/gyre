## Verified working

- **API-contract-change route is real detection, not a marker proxy.** `detect_breaking_changes_on_push` (git_http.rs) now extends `detect_breaking_commits` output with `detect_api_contract_changes` *before* the empty early-return, so both routes feed the same `process_breaking_changes` gated on `list_dependents` identically. The contract route runs a real `git diff --name-status old new` through the existing `parse_name_status` tree-enumeration helper (reused, not duplicated — the coordination requirement), reads the contract at both shas via the real `read_git_file` (`git show <sha>:<path>`), and diffs the parsed operation sets: an operation present in old and absent in new produces `(new_sha, "API contract change: removed {METHOD} {path} from {file}")`. Status handling is correct: M (both sides at the same path), R (old side at the old path, new side at the new path — verified against git's actual `R100\told\tnew` output), D (every old operation removed), A (additive by definition, no old side read). Additive-only pushes return no changes. Branch creation (zero old sha) returns early. An unparseable or unreadable contract on either side logs a `warn!` and skips the route for the whole push — fail-closed, no fabricated empty operation set, no panic.
- **MCP orchestrator notification (step 3b) is a real Directed bus message.** In `process_breaking_changes`, alongside the unchanged `notify_rich` member notifications and the Workspace-destination broadcast, the dependent repo's live orchestrator is resolved via `signal_chain::find_live_repo_orchestrator` (visibility widened to `pub(crate)` only) — the same agent source `list_repo_orchestrators_core` reads (`agents.list_by_workspace` filtered to `RepoOrchestrator` + live, plus the repo_id match that picks *this* dependent repo's orchestrator). The notification is emitted through `emit_event` with `Destination::Agent(orchestrator_id)` and the full payload (source repo id + name, description, breaking-change id, dependent repo id, dependency edge id, commit sha). Persistence-until-acked verified against the adapters: `emit_scoped_event` stores non-Broadcast messages via `messages.store`; `expire_events` excludes agent-destined rows (`to_type.ne("agent")`) and `expire_acked_inboxes` reclaims only acked rows. `gyre_message_poll` (`handle_message_poll`) serves exactly that inbox — `list_unacked(&agent_id)` filters `to == Destination::Agent(agent_id) && !acknowledged` (mem, sqlite, postgres).
