## Verified against the acceptance criteria

- **Structural consistency (step 5)**: `check_bundle_consistency` is pure and I/O-free (architecture lint confirms domain has no I/O). Because the task-142 bundle format carries a single top-level `mr_id`/`spec_ref` (per-gate MR identity is bound by construction), the check enforces the invariants that make that binding sound: non-empty mr_id/merge_commit_sha, version pin, well-formed `path@sha` spec_ref, approval⇔spec_ref linkage, per-gate signature presence, signing-party table (agent gates must be agent-signed by the recorded reviewer; command gates forge-signed — enforced in *both* directions, with a strong test where a forge-key-resigned agent gate still fails), author oidc_sub⇔agent_id binding. - **Cryptographic verification (steps 1–3)**: `ForgeAttestationVerifier` (server, wired into `AppState.attestation_verifier` via both `build_state` and the mem test state) runs real `ring` Ed25519 verification (`verify_ed25519`) against real key material — the forge server key (public half at `/.well-known/jwks.json`, the instance's OIDC issuer key) for bundle signatures and forge-signed gates; per-agent re-derived keys for `agent:<id>` signers; the spec-approval signature over `unsigned_spec_approval_json` for agent approvers. No structural-only checks anywhere. Fail-closed throughout: unknown signer identity → `Ok(false)`; verification error → `unwrap_or_default()` (bool default false) with the result bound before consumption; user-approver Sigstore signatures → `Err` → scored `Some(false)` with a finding, never silently passed. Honest tri-state for absent approval signatures (`None` + explicit finding, not counted as passed crypto).

- **CLI `gyre verify-attestation <commit-sha>`**: reads the bundle via real `git notes --ref=refs/notes/merge-attestations show` (arg-array invocation, no shell), POSTs to the endpoint, prints a per-component human-readable result, exits 1 on failure. Documented in `docs/cli.md`.
