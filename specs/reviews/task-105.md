## Findings

- **F1 (minor, CI-blocking): unused import fails the CI clippy gate.** `crates/gyre-server/src/siem.rs:474` — `use gyre_domain::AuditOutcome;` inside the new test `forward_cycle_sends_decompressed_detail_for_compressed_events` is redundant (`make_event` at siem.rs:375 uses the fully-qualified `gyre_domain::AuditOutcome::Success`). rustc emits `unused_imports` on this line (reproduction: `cargo test -p gyre-server --lib --no-run`, output saved in review-evidence/unused-import-repro.out). The line is inside the hunk added by this candidate (`@@ -464,0 +465,84 @@`), and the CI clippy job (`python3 scripts/check-clippy-diff.py HEAD^1`, ci.yml) fails on any warning whose primary span is on a changed line — so CI goes red on this candidate. Fix: delete the import. Verifier should confirm with `python3 scripts/check-clippy-diff.py <base>` (the review-stage wrapper rejects workspace-wide `--all-targets` clippy; see review-evidence/clippy-gyre-server.out).
- **F2 (minor, edge case): agent-log line-cap eviction inverts when the cold segment is at capacity — newest lines are dropped instead of oldest.** `AgentLogBuffer::trim_to_cap` (log_compression.rs) drains only hot lines: with a 10,000-line cold segment (all lines aged 7–30 days — reachable when an agent emits ≥10k lines, goes quiet past the 7-day fold threshold, and the compression job folds the whole buffer), every subsequently appended line is immediately drained (`surplus.min(self.hot.len())`), so `GET /api/v1/agents/{id}/logs` and TTY replay serve only the stale cold lines until the 30-day retention purge frees them. The previous plain-`Vec` implementation dropped the oldest lines and kept the newest 10k; the Shipped notes' claim that "the 10k-per-agent line cap [is] preserved" holds for the count but not the eviction policy in this state. Live SSE broadcast is unaffected (it bypasses the buffer). Fix: when the hot drain is insufficient, decompress and rebuild the cold segment minus its oldest surplus lines (the mixed-segment rebuild machinery in `purge_older_than` already exists), or cap the cold segment below MAX so hot lines always retain room.

## Minor (non-blocking, recorded for completeness)

- `AgentLogCompressionStats.lines` is documented as "Lines folded into cold segments" but counts the whole rebuilt segment (cold + newly folded) on every pass that folds anything — folding one new line into a 9,999-line segment reports `agent_log_lines_compressed = 10000`. The run log metric therefore overstates per-run work; the tests disclose this ("whole rebuilt segment counts"). Consider counting only newly folded lines for the logged metric.
- `AgentLogBuffer::get`/`replay` decompress the entire cold segment per read even when `limit` is small (bounded at 10k lines/agent — a latency quibble, not a defect).
- Postgres adapter for `compress_details_before` is code-mirrored with SQLite but not integration-tested — consistent with the repo-wide pattern (Postgres is never integration-tested; SQL portability is covered by check-migration-sql-portability), not a finding against this task, matching the task-207 review's scope note.
