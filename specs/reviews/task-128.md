## Findings

- **F1 (major, code — attribute provenance): membership-sourced subject attributes are claim-spoofable on non-workspace-addressed routes.** `crates/gyre-server/src/abac_middleware.rs`. `merge_jwt_claims` (insert-only) runs *before* membership extraction, and the membership block overwrites `subject.workspace_role` only when `resource.workspace_id` is resolved (setting `workspace_ids`/`team_ids` only when memberships exist). Spec §Attributes fixes the sources as Membership/Memberships/Team memberships, but on repo-parented or unscoped routes a verified JWT claim defines the attribute. Reproduced end-to-end at the candidate: ReadOnly user, **no memberships**, test-signed JWT carrying `"workspace_role": "Admin"` → **200 OK** on `POST /api/v1/repos/repo-1/specs/assist` against a tenant Allow keyed on `subject.workspace_role == "Admin"` (decision audit shows the matched Allow); identical request without the claim → 403 default-deny. Beyond granting, the channel **evades Denies**: the spec's own persona-management example (`subject.workspace_role NotIn [Owner, Admin]`) fails to match a real Viewer whose token carries `workspace_role=Admin`, so the underlying Allow proceeds. The candidate's insert-only merge protects the extractor-set identity facts but leaves the membership-sourced names claim-definable — the shipped summary's "claims cannot override extractor-resolved identity facts" is accurate but the coverage row 3 claim "workspace_ids/team_ids/workspace_role from membership/team stores" is falsifiable on these routes. Same class: `subject.persona`/`subject.attestation_level` merge/normalize from claims for **human** subjects too (`normalize_agent_jwt_attributes` is not gated on `subject.type == agent`), though the spec sources them from "Agent OIDC claim". Exploitation requires the IdP to emit such claims (non-default configuration), but the engine must honor the spec's source column. Remedy: exclude `workspace_role`/`workspace_ids`/`team_ids` from raw-claim merging (reserve the keys, or allowlist claim merging to the agent-claim attributes and gate on agent subjects), plus killing tests in both directions (claim must not satisfy a workspace_role-keyed Allow; claim must not evade a workspace_role-keyed Deny).
- **F2 (minor, process): coverage row 3 overstates resource-attribute extraction.** `specs/coverage/system/abac-policy-engine.md` row 3 says `team`/`visibility` come "from real store lookups per resource type", but no code path ever sets `resource.team` or `resource.visibility` (the code's own doc comment concedes "none today"). Fail-closed absence is correct given no entity carries those fields, but the evidence note should scope the claim to what is actually populated.
