## Verified working

- **Archived push rejection (§API Summary / §4 step 5).** `git_info_refs` rejects the `git-receive-pack` advertisement for archived repos with a 200 whose pkt-line stream carries `ERR push rejected: repository is archived` — the git-smart-HTTP service-error convention, so `git push` actually prints the reason instead of swallowing a bare 403 body. Framing independently verified against `pkt_line()`/`service_header()` (`001f# service=git-receive-pack\n0000` + the ERR pkt-line); the unit test hardcodes the framing so a regression in those helpers fails it. `git_receive_pack` (POST) keeps a defense-in-depth 403 after `resolve_repo_by_slug()` and before packfile processing, in the same position as the pre-existing `is_mirror` rejection. Clone/fetch on archived repos still works (read-only, not invisible) — covered by a dedicated advertisement test. The integration test `push_to_archived_repo_rejected` drives a real `git push` (archive via API → clone → commit → push → assert failure naming "archived").
- **Admin Repos tab (§Repos Tab).** `WorkspaceSettings.svelte` TAB_IDS includes `repos`; the tab lists all workspace repos with name, Active/Archived status badge, active agent count (from `GET /agents?workspace_id=`), last activity (max of repo.updated_at / agent spawn / MR timestamps), default branch and mirror URL; "+ New Repo" and "Import Repo" buttons open the creation/import forms wired to `api.createRepo`/`api.createMirrorRepo`; clicking a repo navigates to repo scope via the new `goToRepo` context (App.svelte). Status strings match the server's `RepoStatus` Display impl ("Active"/"Archived").
- **Gate config UI (§Gates).** `RepoSettings.svelte` gates tab: per-gate enabled/disabled toggle, "+ Add Gate" with type selector (pre-existing), per-gate Configure form (name, command / required_approvals / persona by type, timeout), delete, and drag-to-reorder that rewrites 1-based positions through the PUT endpoint and reloads from the server on failure. Backend `PUT /api/v1/repos/:id/gates/:gate_id` (`update_gate`) does partial updates with per-type validation (command rejected on non-command gates, non-empty name, cross-repo gate id → 404), and the route is registered on the existing ABAC-mapped path. The `position` field is a real persisted column (migration `2026-10-08-000062_gate_position`, backfill 0, ordering `(position, created_at)`), enforced identically in the SQLite adapter, the PostgreSQL adapter, and the mem adapter (which gained the same sort contract in code — port-contract invariant respected). `list_gates`, the SQL adapters, and the mem adapter all agree on the ordering; API test `list_gates_orders_by_position` covers create-with-default-positions and reorder-via-PUT against the real router.
- Tests are not self-confirming: the pkt-line test hardcodes framing rather than mirroring `pkt_line()`; the adapter upsert test asserts every mutable column including `position`; the frontend tests assert exact API call payloads (`{ required: false }`, position sequences) and would fail if the wiring changed; the drag test asserts the untouched gate is not re-PUT.
