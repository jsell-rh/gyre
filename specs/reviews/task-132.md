## Verified

- **All six §UI features are real production code**, not stubs: PolicyManager (scope selector + scope_id filter, policy table, CRUD, view tabs), PolicyEditor (visual condition builder — add/remove rows, §Attributes datalist autocomplete covering Subject/Resource/Environment, all 8 operators, typed value serialization: `in`/`not_in`→arrays, `greater_than`/`less_than`→numbers, `exists`→null), PolicySimulator (POST /policies/evaluate with subject/action/resource + scope chain; displays decision/matched policy/evaluated count/evaluation ms), PolicyDecisionLog (server-side subject_id/resource_type filters, client-side allow/deny + date-range), EffectivePermissions (per-resource-type GET /policies/effective?subject=), and the client-side conflict detector (lib/abac.js).
- **Conflict detector mirrors the engine faithfully**: `scope_applies` semantics (same scope + null scope_id = all at level; unscoped broader scope contains narrower) and §Policy Composition winner rules (immutable Deny → priority → scope specificity → Deny-over-Allow) — cross-checked against `policy_engine.rs` `scope_applies`/`evaluate`/sort key. The one conservative skip (a scope_id'd tenant policy vs a workspace policy — overlap depends on entity ownership the client can't see) is documented in-code and tested.
- **Server change is minimal, spec-required, and tested**: `parse_scope` in `api/policies.rs` was case-sensitive, so the spec-documented `?scope=Workspace&scope_id=` query form (which the pre-existing `api.workspaceAbacPolicies` helper already sends) returned 400. The fix (case-insensitive match) plus `list_policies_scope_query_is_case_insensitive` (asserts capitalized lists the policy, lowercase still works, other scope_id does not) closes it. No new routes → no ABAC registry changes needed.
- **Settings integration at all three scope levels** — TenantSettings (tenant scope, admin's tenant prefilled from `me()` — `/users/me` does return `tenant_id`), WorkspaceSettings (locked workspace scope, existing trust summary preserved), RepoSettings (locked repo scope); each covered by a test asserting the `?scope=…&scope_id=…` query params. The removed TenantSettings primitive form left no dead references.
