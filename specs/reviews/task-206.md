Findings (all three were durable findings from Round 1, unfixed in this candidate):

- **F1 — REST ceremony bypass via agent complete (code, `crates/gyre-server/src/api/spawn.rs`).** The §5 skip-ceremony invariant is enforced only in the MCP dispatch. `POST /api/v1/agents/{id}/complete` accepts the preview agent's own live JWT and performs everything §5 forbids: creates a real MR on the preview branch, transitions the agent to `Idle` (violating "Preview agents are killed on completion (no idle state)"), writes `agent_provenance` kv, and writes `refs/agents/{id}/snapshots/*` (violating "No refs, no provenance"). Empirically confirmed on this candidate: 201 Created with agent_status=Idle, provenance_kv=true, snapshot ref present (probe log, run 1). Reproduce: `cargo test -p gyre-server --test preview_ceremony_probe` with the source at `/tmp/stage/review-evidence/probe-rest-ceremony-bypass.rs`. Fix direction: gate `complete_agent` on `meta_specs::is_preview_agent` (route preview agents to `finish_preview_agent` or reject with 403), mirroring the `mcp.rs` guard.
- **F2 — REST ceremony bypass via MR creation (code, `crates/gyre-server/src/api/merge_requests.rs`).** `POST /api/v1/merge-requests` has no preview-agent gate and accepts a live preview-agent JWT: 201 Created, real open MR (probe log, run 2). `repository_id` is caller-supplied, so a preview agent — running code guided by an uncommitted draft meta-spec — can open MRs on any repo its Agent-role ABAC policy allows, not just its own preview branch: a scope escape beyond §5's "no MR" skip. Fix direction: reject MR creation for preview agents (same `is_preview_agent` gate) and/or have `teardown_preview` close MRs already created on `preview/{id}/*` branches.
- **F3 — SSH preview agents are killed on the wrong machine (code, `crates/gyre-server/src/api/spawn.rs`, `kill_process_handle`, lines 753-763).** The function dispatches only `container` vs. everything-else→`LocalTarget::kill_process`, but an SSH compute target's `ProcessHandle.pid` is the *remote* pid echoed by the remote shell (`compute/ssh.rs` `spawn_process`: `... & echo $!`, `target_type == "ssh"`, handle id `user@host:pid`). `DELETE /api/v1/meta-specs/preview/{id}`, the GC sweep, and the admin kill path (admin.rs:279) therefore run `kill -TERM <remote-pid>` **locally** when a preview agent was spawned on an SSH target: the remote preview process keeps running, and whatever local process happens to hold that pid is terminated — an unrelated-process kill. Confirmed by inspection: `kill_process_handle` has no `ssh` arm; `SshTarget::kill_process` exists and is the correct dispatch. Fix direction: add an ssh arm that reconstructs an `SshTarget` from the handle (handle.id is `user@host:pid`) or records enough target info on the handle to dispatch ssh kills to `SshTarget::kill_process`.
