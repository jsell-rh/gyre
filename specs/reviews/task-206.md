## Findings

- [-] **F1 (major — empirically confirmed, base-controlled): the candidate breaks two mechanically-enforced gate scripts.** The diff's rustfmt churn in `crates/gyre-server/src/merge_processor.rs` and `crates/gyre-server/src/api/recovery.rs` (regions unrelated to preview mode) shifted pre-existing line-pinned exemption sites: `evaluate_attestation_abac` 1457→1455 and 1479→1477 (vs `scripts/inert-enforcement-exemptions.txt`), `resolve_ref(...).unwrap_or_default()` 224→227 and 275→279 (vs `scripts/fail-open-ref-resolution-exemptions.txt`). `bash scripts/check-inert-enforcement.sh` and `bash scripts/check-fail-open-ref-resolution.sh` exit **1** on the candidate and **0** on a pristine worktree of base `3c39ab1f` (control logs retained). Both are blocking pre-commit hooks (`.pre-commit-config.yaml`); CI runs them advisory. Remedy: move the pinned exemption lines to follow the sites — never add entries.
- [-] **F2 (major): §5 skip-ceremony is not enforced on the REST task routes.** `create_task` (`crates/gyre-server/src/api/tasks.rs:177`) and `update_task` (`tasks.rs:281`) have no auth extractor and no preview guard. A preview agent's live JWT authenticates as `UserRole::Agent` (`auth.rs:653`), and builtin policy `agent-scoped-access` (priority 700, `abac_middleware.rs:607`) allows the Agent role `write` on `*` — so a preview agent can create and mutate task-ledger rows via `POST/PUT /api/v1/tasks`, the exact escape class the review-fix round closed for `POST /agents/{id}/complete` and `POST /merge-requests`, and which the MCP dispatch already refuses for the equivalent tools (`gyre_create_task`/`gyre_update_task`). The shipped claim "enforced on every surface a preview agent can reach" is inaccurate. (`merge_queue::enqueue` has the same missing guard but requires an existing MR — same class, lower reachability.) Remedy: gate the task routes (and merge-queue enqueue) on `caller_is_preview_agent` the way `create_mr` does. Verifier probe: mirror `preview_agent_rest_ceremony_is_refused` with `POST /api/v1/tasks {"title":"escape"}` using the preview agent's JWT — current code returns 201; §5 requires 403.
- [-] **F3 (moderate): the workspace-budget path over-admits multi-target preview requests.** `post_meta_spec_preview` Pass 2 runs `budget::check_spawn_budget` per target before any increments (increments happen in Pass 3), and `check_spawn_budget` compares only current usage vs max. A single POST with N targets against a workspace with `max_concurrent_agents = M < N` admits all N. The `GYRE_PREVIEW_BUDGET_MAX_CONCURRENT` path correctly accounts for `requested`; the default workspace-budget path — the spec's default — does not. Remedy: account for the in-flight request count (per-workspace aggregation of `resolved`) in the workspace-budget branch.
- [-] **F4 (process): the rebase merge commit `f092e666` is absent from task-206's `commits:` frontmatter at HEAD.** `f092e666` ("fix(task-206): resolve rebase onto main — §5 client contract reconciliation") touches product surface (`web/src/lib/EditorSplit.svelte`, `web/src/__tests__/EditorSplit.test.js`, `web/src/locales/en.json`, `web/dist`, `specs/coverage/system/ui-layout.md`). The head process commit `88839d82` removed it from the frontmatter (its parent `c706391e` had added it), while the Shipped notes still claim it is "recorded in `commits:`". `check-task-commit-attribution.sh` passes only because it scans `--no-merges` and `f092e666` is a merge commit — per AGENTS.md the unlisted commit is invisible to verifier review scoping. Remedy: re-add `f092e666514102d2cff10a8d330b788e5520b5ab` to the frontmatter.
