## Observations (non-blocking, recorded for task-143/144)

- **Placeholder key scheme, as the task authorizes.** `GateAgentSigner` keys are derived from the forge key (`SHA-256(forge PKCS#8 ‖ domain ‖ agent_id)`), so a forge-key holder can re-derive agent keys. The task explicitly permits a placeholder ("HMAC or a placeholder — Sigstore/OIDC integration comes later"), the shipped notes and coverage row disclose the placeholder, and `verify_merge_attestation_bundle` documents that external verification arrives with OIDC. Consequence to carry forward: coverage row 13's phrase "distinct from the forge key, so the forge alone cannot forge a complete bundle" overstates what distinct derived keys prove — keys are distinct, but forge-derivable. The spec's true no-single-forger property lands only with task-143/144's OIDC identities; the wording should be tightened when those close. Not fake completion: the deferral is explicit and tracked.
- **Timestamps are Unix epoch seconds (u64)**, not the ISO-8601 strings in the spec's illustrative JSON example. The task's implementation plan mandates `merged_at: u64`, and every sibling timestamp in the domain (`GateResult.started_at/finished_at`, MR timestamps) is already epoch u64 — ISO strings here would be inconsistent with the codebase. All schema fields are present; if the spec's ISO form is meant normatively, amend the spec via lifecycle rather than diverging silently.
- `AttestationSigner::signer_identity()` has no production caller — `signed_by` is set from literals that mirror it (`"forge"` / `agent:<id>`), in the same file, pinned consistent by the tests. Cosmetic duplication only; the trait method is part of the task's required port shape.
