## Verified working

- **Entity/enum match spec.** `WorkspaceMembership` (gyre-domain/src/workspace_membership.rs) carries id, user_id, workspace_id, role, invited_by, accepted_at, created_at (plus a documented `accepted` flag for the pending-invite flow); `WorkspaceRole` is Owner/Admin/Developer/Viewer.
- **Membership management is real and scoped.** POST/GET/PUT/DELETE `/api/v1/workspaces/:id/members...` plus the spec-named alias `PUT .../members/:user_id/role`: tenant-scope gate (`load_workspace_scoped`, cross-tenant 403, fail-closed on unresolvable workspace), capability gate (`can_manage_membership`: system principal, platform Admin/TenantAdmin resolved from the stored record, or workspace Owner/Admin membership), invitee must exist in the workspace's tenant (cross-tenant sharing refused), duplicate invite 409, `WorkspaceMembership` now wired through `store!` so DB-backed deployments persist it (was unconditionally mem before).
- **Last-Owner protection.** `update_member_role` and `remove_member` both count *active* Owners (membership role Owner AND user record exists) excluding the target and return 409 on zero — removal and downgrade are both blocked; test `last_owner_cannot_be_removed_or_downgraded` asserts 409 on both paths plus membership survival.
- **Ownership transfer is audit-logged.** Any role change involving Owner emits `workspace_ownership_transferred` with previous/new role, previous owner, actor, and caller-supplied reason; test queries the audit store and asserts exactly one event with the recorded reason; reassignment clears the ownerless record immediately (`clear_ownerless`).
- **TenantAdmin reassignment path is ABAC-permitted.** The member PUT resolves to the `transfer_ownership` ABAC action (new `method_action_overrides` on the route mapping, applied to both the M22.8 route and the spec alias); builtin `workspace-member-management` (priority 810) allows it for `subject.workspace_role In [Owner, Admin]`, and TenantAdmins pass via the pre-existing `builtin-admin-all-operations` (platform-Admin role, which every provisioning path couples to GlobalRole::TenantAdmin — verified across users.rs/SCIM creation paths).
- **Ownerless notification.** `workspace_ownership.rs`: when a workspace with a surviving Owner-membership row loses its last active Owner, every TenantAdmin **of that workspace's tenant** gets a priority-2 `WorkspaceOwnerless` notification (new NotificationType with as_str/from_str/priority_rank wiring); plain members and other tenants' admins are excluded (tested); dedup prevents job-rerun stacking (tested). Triggered inline on SCIM user deletion (`on_user_removed`) and by the daily `orphaned_workspace_check` job registered in jobs.rs. Never-owned workspaces (system/agent-created) are correctly not flagged — the spec trigger is an owner *departure*; the repair round 93c4017 fixed the earlier false-positive class and the test `never_owned_workspace_is_not_tracked_or_notified` pins it. Workspace creation by a user principal now seeds the creator's accepted Owner membership, so fresh workspaces are not flagged.
- **Orphaned detection, 30-day configurable.** Ownerless records persist in the port-backed `kv_store` (`workspace_ownership` namespace); `GET /api/v1/admin/orphaned-workspaces` (registered + ABAC-mapped as admin resource) returns workspaces ownerless ≥ `GYRE_ORPHANED_WORKSPACE_DAYS` (default 30) with ownerless_since and days; threshold behavior tested at 30 vs 60 days.
- **Repo access per spec table.** `RepoPermission` sets in gyre-domain/src/repo_access.rs match the table exactly (Owner adds ManageBudget; Admin lacks it; Developer lacks Admin/ManageGates/ManageBudget; Viewer read-only) — pinned by four table tests.
- **Restrict-only overrides, end to end.** `RepoAccessOverride` port + mem/SQLite/PostgreSQL adapters + portable migration 000060 (UNIQUE(repo_id, user_id) as backstop). `validate()` rejects an override more privileged than the membership role (400), the effective role is `most_restrictive(workspace, override)` — the mutation probe proves the domain tests kill an inversion. git_http's `authorize_repo_access` enforces the effective permission set on the real transport: upload-pack → Read, receive-pack → Write, denial records an `RbacDenied` audit event; the transport test drives real user principals (Developer OK/OK, Viewer OK/403, outsider 403, overridden Developer keeps fetch but loses push).
- **ABAC integration.** `subject.workspace_role` is resolved in the middleware from the real membership store for workspace-addressed routes (path param) and repo-addressed routes (repo → workspace lookup, fail-closed on unresolvable repo), using the axum `MatchedPath` pattern. The repo-access API tests run the **production pipeline** (router + abac_middleware + seeded builtin policies): a workspace Admin with plain-Developer global role is allowed via `builtin-repo-access-override-management` (decision-record asserted), a Developer member is 403'd by the policy layer, and `member_management_requires_owner_admin_or_tenant_admin` proves a Developer's 403 comes from the handler with an Allow decision recorded.
- **No test inflation found.** New tests drive real routers/transports and assert on stored state (memberships, audit events, notifications, policy decisions); the duplicate-409 mapping has a chain-matching test reproducing each adapter's error shape; the fail-closed dangling-workspace test creates a repo pointing at a missing workspace.
- **No web/dist concern** (no web sources touched; task-208's stale-bundle class does not apply).
