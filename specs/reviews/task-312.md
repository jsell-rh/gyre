## Verified working

- **Bootstrap** (`scripts/dev-platform.py`): idempotent start/stop/status; builds with SKIP_WEB_BUILD=1, dedicated port + SQLite dir, provisions workspace/repo/Developer service principal + API token over real REST with the system bootstrap token, registers `platform_endpoint/token/workspace/repo` via the existing `store.setting` mechanism. Health check, lost-token re-provisioning, and duplicate-free re-provisioning are test-covered; every route and response shape matches the real server.
- **Shared state** (`scripts/pipeline/platform.py sync`, wired into `catalog.sync_checkout`): upserts every task untyped with title/spec_ref/priority/order and depends_on edges resolved through the persisted `platform_tasks` mapping; dependency-order fixpoint; idempotent re-sync; create-only drift and reopened terminal records supersede + re-register (the platform's `done` is terminal — verified against the domain transition table). Sync failures are durable events and never break discovery.
- **Lifecycle write-back**: admission pushes in_progress under the lease heartbeat; the publication path (`updates.progress == 'complete'` / `delivered` — exactly the `stages.py` publication updates) pushes done; a structural runtime hold (the setting `store.retry` writes for attention categories) pushes blocked. All three hooks sit at the correct points in `run_claim`; failed pushes are reconciled by sync.
- **Authoritative sequencing**: the gate in `eligibility.eligible` applies to non-claimed implement work and runs inside the claim transaction on both admission paths (`dev-pipeline.py run_one` and `dispatch-adapter.py authorize/launch`). The platform's answer is authoritative (not-done blocks admission even when local state satisfies it — the mirror-probe test drives the real claim path); unmapped dependencies fail closed; unavailability records a durable `platform_unavailable` event and admits nothing, while the post-execution recheck skips claimed rows so in-flight work proceeds. The per-process index cache is safe: every admission cycle is a fresh process (`serve` execve's the Go dispatcher, which spawns one-shot adapter processes).
- **No spawn surface**: no orchestrator-spawn route, no `gyre_spawn_worker`, no `task_type` in any created record; the scheduler provably never spawns untyped tasks. Task writes use only the Developer service token (never the admin token); all task routes are in the ABAC registry, so the real policy engine evaluates them.
- **Docs**: `docs/dev-pipeline.md` now presents the platform as the task-state/sequencing authority, keeps `pipeline.sqlite3` as the telemetry ledger, and records the staged progression (next: scheduler-driven task-to-agent mapping per the amended agent-runtime contract) — replacing the bespoke-ledger-as-permanent-authority framing the gap cited.
