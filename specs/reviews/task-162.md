## Verified working (no findings)

- **Dispatcher is real and single-owner.** `spawn_message_consumer()` (`message_dispatcher.rs:80-97`) takes the mpsc receiver via `AppState::take_message_dispatch_rx()` (Mutex<Option<Rx>>, second call is a logged no-op) and spawns `MessageDispatcher::run`, which drains and awaits every registered `Arc<dyn MessageConsumer>`. `MessageDispatcher` holds `Vec<Arc<dyn MessageConsumer>>` per plan. Called once from `main.rs` after `build_state`.
- **Send-path wiring per spec.** `AppState::emit_event` (lib.rs:615-634) stores → signs → WS-broadcasts → `try_send` clones into the 256-capacity channel, with warn-on-full / debug-on-closed (spec's "dropped with a warning log, never blocks"). The REST (`api/messages.rs:313`) and MCP (`mcp.rs:2157`) `try_send` clones pre-exist unchanged at the base. The no-op drain loop at the base is removed in both `build_state` and `mem::test_state_inner`.
- **NotificationBridge is a real consumer with real persistence.** `on_message` matches `GateFailure`/`BudgetWarning`/`AgentError`/`ReconciliationCompleted` and creates notifications through `notifications::notify_rich` (single creation path, structured source + deep link). Tenant is resolved from the workspace record with skip-on-missing (no fabricated "default" scope). GateFailure resolves MR → author agent → `spawned_by`; AgentError resolves agent → `spawned_by`; BudgetWarning/ReconciliationCompleted fan out to Admin/Developer/Owner members (Viewer excluded).
- **Gate-failure rewiring is complete, not additive.** The synchronous `notify_gate_failure` path in `gate_executor.rs` (which hardcoded `tenant_id: "default"`) and the `notify_gate_failure` helper are removed; the pre-existing `GateFailure` event emission in `run_gate` (gate_executor.rs:110-148) is the sole trigger, consumed by the bridge. HSI §8 p3 was amended in `specs/system/human-system-interface.md` to document the route change (goal rule 4: amend the spec, don't contradict it). The bridge resolves the tenant properly, strictly improving on the removed hardcoded-"default" path.
- **ReconciliationCompleted single path.** The inline MetaSpecDrift creation in `emit_reconciliation_completed` is removed; p6 notifications now flow only through the bridge, per HSI §8 p6 ("Via MessageConsumer consuming ReconciliationCompleted events") which already specified this route. The affected test was updated to spawn the real dispatcher and poll.
- **TTL expiry job matches plan.** `spawn_message_expiry` (hourly 3600s, `MissedTickBehavior::Delay`, first tick at startup) calls `run_message_expiry`: `expire_events(now − GYRE_EVENT_TTL_SECS·1000)` + `expire_acked_inboxes(now − GYRE_DEAD_INBOX_TTL_SECS·1000)`, defaults 604800 each, `env_u64` warn-on-invalid. Wired in `main.rs`. Registered as `message_expiry` in the admin job registry (`jobs.rs`) for on-demand `POST /admin/jobs/message_expiry/run` — same register-plus-own-loop pattern as merge_processor/stale_agent_detector; `JobRegistry::register` does not spawn a loop, so there is no double periodic execution.
- **Mem adapter contract parity (invariant class: every port constraint enforced by every adapter).** `MemMessageRepository` gains `ack_reasons` mirroring the SQLite `ack_reason` column: `acknowledge` records "explicit" (and is now idempotent-guarded like SQLite's `WHERE acknowledged=0`), `acknowledge_all` records the passed reason, and `expire_acked_inboxes` deletes only agent-targeted messages with reason `agent_completed`/`agent_orphaned` older than the cutoff — matching `sqlite/message.rs:400-421` exactly. Lock order (store → ack_reasons) is consistent across all three methods.
- **Tests are hard, not self-confirming.** `message_expiry_deletes_old_events_and_dead_inboxes` stores five messages through the real repository and asserts retention boundaries (unacked Directed and explicit-ack retained; only expired Event-tier and `agent_completed` inbox deleted) — fails if `expire_events` ever sweeps Directed tier or reasons are ignored. `message_expiry_env_ttl_respected` (1s vs 1000s TTL) fails if the env var is not read (with the default TTL the ancient event would be retained → count 0). `spawn_message_consumer_end_to_end` and `failed_gate_creates_gate_failure_notification_via_bridge` go through the real `emit_event`/`run_gate` paths and poll for exactly one notification (type, rank, tenant, source entity) — they fail if the dispatcher, the bridge, or the gate-executor event emission breaks. The two env-mutating TTL tests serialize on a module mutex. `gate_failure_notification_carries_deep_link` (notifications.rs) now drives the bridge and still asserts the deep link.
- **No new dead MessageKinds.** The bridge's `BudgetWarning`/`AgentError` handlers correspond to kinds that have no production emitter today — a pre-existing gap documented in the frozen `scripts/dead-message-kind-exemptions.txt` (unchanged by this candidate; `check-dead-message-kinds.sh` passes). Budget-warning notifications are still delivered by the pre-existing synchronous path (`api/budget.rs maybe_notify_budget_threshold`), so no notification regression and no duplicate fan-out (no emitter → no bridge copy). The handlers are forward wiring explicitly requested by the task plan.
