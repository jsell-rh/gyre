## Verified working (no findings)

- **Dispatcher is real and single-owner.** `MessageDispatcher` (message_dispatcher.rs) holds `Vec<Arc<dyn MessageConsumer>>`; `spawn_message_consumer()` takes the receiver via `AppState::take_message_dispatch_rx()` (`Arc<Mutex<Option<Receiver>>>` — a second spawn is a logged no-op, pinned by `spawn_message_consumer_end_to_end`) and spawns the drain loop. The base's no-op drain task in `build_state`/`test_state_inner` is removed; the receiver is now stored on AppState instead. Wired in main.rs before `build_router`.
- **All three send paths clone into the channel** after store: `AppState::emit_event` (lib.rs, now logs Full/Closed try_send outcomes per spec's drop-with-warning rule), REST `send` (api/messages.rs:313), MCP `gyre_message_send` (mcp.rs:2081). Non-blocking `try_send` throughout — hot path never blocks on consumer latency, per spec.
- **NotificationBridge is a genuine MessageConsumer** (implements the `#[async_trait]` port trait) creating real notifications through `notify_rich` (shared creation path → structured source + deep links): GateFailure→rank-3 for the MR author agent's spawning user (MR→author agent→spawner chain, tenant resolved from the workspace record — the old path passed a literal `"default"` tenant), BudgetWarning→rank-4 for Admin/Developer/Owner members, AgentError→rank-2 AgentEscalation for the spawning user, ReconciliationCompleted→rank-6 MetaSpecDrift for Admin/Developer/Owner. Unknown workspace / missing spawner → skip + warn, never a fabricated identity.
- **Sync duplicate paths removed, not duplicated.** `notify_gate_failure` (notifications.rs) and the gate-executor's inline p3 creation are deleted; `emit_reconciliation_completed` no longer creates MetaSpecDrift inline — one creation path each, via the bridge. The gate executor still emits the GateFailure event (payload matches the bridge's expected schema), so the rewired chain is closed; `failed_gate_creates_gate_failure_notification_via_bridge` pins the whole chain (run_gate → emit_event → dispatcher → bridge → exactly one rank-3 with correct tenant/source). The HSI §8 p3 row was amended to match the canonical message-bus spec text (which the task's spec_ref quotes verbatim: "when it receives a GateFailure message, it creates a notification") — legitimate reconciliation, documented in HSI's amendment table, not a reinterpretation to fit code.
- **TTL job is real and periodic.** `run_message_expiry` calls `expire_events(now − GYRE_EVENT_TTL_SECS·1000)` and `expire_acked_inboxes(now − GYRE_DEAD_INBOX_TTL_SECS·1000)` on the `MessageRepository`; `env_u64` parses both vars with warn-on-invalid fallback to 604800. `spawn_message_expiry` runs hourly (3600s, MissedTickBehavior::Delay, first tick immediate), tracked in the job registry (`mark_scheduled`/`record_cycle`, on-demand `POST /admin/jobs/message_expiry/run`) — same pattern as task_scheduler/stale-agent loops; no double loop (main.rs does not `spawn_job("message_expiry")`). Registered in `start_job_registry` and wired in main.rs.
- **Mem adapter brought up to the port contract** (check-mem-port-contracts passes): `MemMessageRepository` gains an `ack_reasons` map mirroring SQLite's `ack_reason` column — `acknowledge()` records `"explicit"` (now conditional on `!acknowledged`, matching SQLite's `acknowledged=0` filter), `acknowledge_all()` records the passed reason, and `expire_acked_inboxes` now deletes only agent-targeted messages acked `agent_completed`/`agent_orphaned` older than the cutoff (previously it deleted *all* acknowledged messages — a real cross-adapter contract bug fixed). Lock ordering store→ack_reasons is consistent across all three methods.
- **Tests are hard, not self-confirming.** TTL tests would fail on the specific regressions they name: hardcoded default TTL → `message_expiry_env_ttl_respected` fails (1s TTL must delete the 10s-old event only); over-broad `expire_events` → "unacked Directed retained" assert fails; over-broad dead-inbox sweep → "explicit-ack retained" assert fails. Bridge tests assert count, type, rank, tenant, and source entity per recipient (including Viewer-role exclusion and unknown-workspace skip). Env-mutating tests serialize on a module mutex. The two async-path tests poll (100×10ms) rather than assuming synchronous delivery — correct for a background dispatcher.
