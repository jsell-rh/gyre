## Minor notes (non-blocking)

- **At-least-once decomposition on crash:** a process crash (or tasks-update failure) between sub-task creation and the delegation's Done transition leaves the task InProgress; the stale re-claim re-runs decomposition and would duplicate the sub-task set (no idempotency key on `parent_task_id`). Narrow window, bounded by crash/DB failure, consistent with at-least-once task processing; the concurrent-cycle and double-claim races (the realistic ones) are guarded and tested.
- **Phase 2 run is deterministic:** the workspace orchestrator's cross-repo impact analysis is the structural `spec_links` query — no LLM judgment call in the Phase 2 run itself (Phase 3 decomposition and coordination assessment do use the LLM when configured). The persona agent is spawned per spec, and the acceptance criteria do not require a Phase 2 LLM call.
- **Process-local registry/claims:** the mutexes and the non-atomic Backlog claim are process-local (documented in code); the durable one-live guard for agent spawn remains the spawn core's DB check. Single-server deployment assumption.
