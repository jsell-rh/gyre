# Gyre Server Configuration

## Running the Server

```bash
# Dev mode (defaults: port 3000, token gyre-dev-token, in-memory DB)
cargo run -p gyre-server

# With custom settings
GYRE_PORT=8080 GYRE_AUTH_TOKEN=my-token GYRE_DATABASE_URL=sqlite:///tmp/gyre.db RUST_LOG=debug \
  cargo run -p gyre-server

# Release build
cargo build --release -p gyre-server && ./target/release/gyre-server
```

Access at `http://localhost:3000`. Default token `gyre-dev-token` works against a local dev server.

**Dev mode vs production (protocol injection parity):** `gyre bootstrap --dev` skips OIDC and uses static-token auth (single tenant/workspace). Agent spawn and prompt injection are identical in both modes — the four system prompts (persona, protocol norms, context, constraints) and the persona attestation variables are assembled from the task/repo/workspace/budget state at spawn time, not from the caller's OIDC claims, so dev-mode agents receive the full protocol injection. The only difference is caller authentication (static token vs OIDC JWT); there are no protocol-injection gaps in dev mode. The spawn-injection tests run under exactly the dev-mode server configuration (static-token auth, no JWT/OIDC config), so this parity is regression-tested.

| `GYRE_AGENT_SIGNING_KEY` | _(unset)_ | Operator-provisioned forge Ed25519 signing key for `local`-mode commit signatures (task-107 F12), as base64-encoded PKCS#8 DER — both v1 and v2 documents are accepted (generate one with `openssl genpkey -algorithm ed25519 -outform DER | base64 -w0`). Rotating to a new key retains the previous key's public material in the durable signing-key history, so `GET /.well-known/jwks.json` keeps serving the old kid and messages signed before the rotation stay verifiable (message-bus.md §Edge Cases "Signature key rotation", task-254). Invalid base64 or non-Ed25519 PKCS#8 material is a hard startup error (no silent fallback to a different key). |

Search order: this variable (authoritative), then `node_modules/typescript/lib` under the analyzed repo, the workspace root, or the language-server install prefix. Note: TypeScript 7 (native) `lib` directories have no `tsserver.js` and are rejected — install a TypeScript 5.x line. When nothing is found, the server attempts its own workspace resolution and Pass 2 degrades if that fails. |

Preview agents are spawned by `POST /api/v1/meta-specs/preview` with the draft carried out-of-band: the container receives `GYRE_PREVIEW_ID`, `GYRE_META_SPEC_DRAFT_KIND`, `GYRE_META_SPEC_DRAFT_CONTENT` and `GYRE_TARGET_SPEC_PATH` on top of the standard spawn vars, and **`GYRE_TASK_ID` is deliberately absent** -- a preview agent has no task. Those agent-side variables are documented in [docker/gyre-agent/README.md](../docker/gyre-agent/README.md).
